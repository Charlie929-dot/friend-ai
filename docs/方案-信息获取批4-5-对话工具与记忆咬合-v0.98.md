### 2.1 信号判定公式（**写死，防动工时读岔**——拍板 #16）

**"这轮要不要启用工具循环"的完整目标形态 =**

```
(MEMORY_TOOLS_ENABLED 且 回忆信号)
或 (LOOKUP_ENABLED 且 ((SEARCH_PROVIDER != "none" 且 (查证信号 或 时效信号)) 或 消息含 https?://))
```

⚠️ ③ 类（贴链接）**在 `LOOKUP_ENABLED` 里面**——"永久可用"指不受 `SEARCH_PROVIDER` 门，**不是**不受任何门。

**词表**（`corpus.py`；会扩充 → 归语料，约定 #3）：

```python
# ①② 查证意图 + 时效词——**与 lookup_online 同 gate**（SEARCH_PROVIDER != "none" 时才算信号）
LOOKUP_SIGNALS = (
    "帮我查|帮忙查|查一下|查下|查一查|搜一下|搜下|搜索一下|"
    "是不是真的|真的假的|真假|靠谱吗|可信吗|多少钱|价格|"
    "最新怎么样|最近怎么样|进展如何"
)
LOOKUP_FRESH_SIGNALS = "今天|现在|目前|今年|刚出|刚发布|最新的|最近|这两天|这几天"
LOOKUP_QUESTIONS = r"[?？]|吗|呢"

# ③ 消息里直接贴了链接 → 触发 tool loop 让 TA 用 open_link 去看
#   （不受 provider 门，但**受 LOOKUP_ENABLED 总门**；默认配置下 open_link 唯一合理的触发面）
LOOKUP_URL_SIGNAL = r"https?://[^\s]+"
```

⚠️ **保守起步**（承 §3.2）：命中率直接决定每轮要不要多跑一次 LLM + 一次网络。③ 类语义信号实测后再补。

### 2.2 【本轮新发现】工具可见性 vs 触发信号：默认配置下 `open_link` 只有一条可用路径

审查指出"`搜一下` 族词与拍板 #1 自相矛盾"。顺着往下查，问题比这更根本：

**默认配置（`SEARCH_PROVIDER=none`）下，工具表里只有 `search_memories` / `recall_detail` / `open_link` 三个，而 `open_link` 需要一个 URL。URL 从哪来？**

- 【我今天刷到的】注入块（`context.py:143-149`）**只渲染 `summary + 出处域名`，不带 URL**——这是 §3.5 刻意的（拟人化不报链接地址；用户要看得去网页端面板点）。
- 所以**模型手里根本没有可供 `open_link` 使用的 URL**，除非 **用户自己在消息里贴了链接**。

于是默认配置下：

| 信号 | 工具表里有没有能干这事的工具 | 结论 |
| --- | --- | --- |
| 消息含 URL | ✅ `open_link` | **应触发**（默认配置下唯一合理的入口） |
| "帮我搜一下/查一下/是不是真的/多少钱" | ❌（`lookup_online` 被 gate 挡着） | **不应触发**——否则白跑一轮 LLM |
| 时效词 + 疑问（"今天天气怎么样"） | ❌ 同上 | **不应触发**——更要命的是模型可能**编一个 URL** 去调 `open_link` |

**定稿口径**：
1. **①② 两类信号与 `lookup_online` 同 gate**——`SEARCH_PROVIDER == "none"` 时**不算信号**（拍板 #11）；
2. **新增第 ③ 类信号 = 消息里出现 `https?://`**，不受 provider 限制，始终可用；
3. `open_link` 的 `desc` 措辞据此调整——原稿"顺着刚才看到的那条，把它整个翻开看看"**与"注入块不给 URL"矛盾**（模型做不到），改为 **"别人给了我一个地址，我可以打开看看"**（✅ 已拍板，拍板 #14）。

> 这样一来，批 4 在默认配置下的**用户可见价值 = "贴个链接让它看"** + 全部基础设施（预算 / SSRF / 注册 / 截断）就位。等哪天你配了搜索源，①② 信号与 `lookup_online` 一起自动生效。**✅ 已拍板（Q4=A）：就按这个交付形态走**；"追问刷到的某条 → 真展开"的诉求走 `open_browsed` 后路（§10）。

## 7. 已知边界（写下来防"忘了"）

- **`open_link` 抓到的内容不入库**：对话结束即失，只有过闸门 3 才留存（拍板 #2）。
- **`open_link` 不写 `info_cache` = 同一 URL 可反复 open**，每次 1 次 fetch + 1 次摘要 LLM，靠预算（1/轮、20/天）兜底——与拍板 #2 是一体两面。
- **默认配置下 `open_link` 的触发面只有"用户贴链接"**：注入块不给 URL（§2.2），所以它无法对"刷到的东西"展开——要改这条就得改 §3.5 的"不报链接地址"，属另一件事。
- **`lookup_online` 默认不可用**：`SEARCH_PROVIDER=none` 时不在工具表里，TA 不会知道有这能力（拍板 #1）。
- **不防 DNS rebinding**：主机名校验拦得住 `127.0.0.1` 字面量，拦不住"域名解析到内网"。自用单用户 + 正文已被摘要层隔离，风险可接受（拍板 #4）。
- **`http://` 明文贴链**：SSRF 的 https-only 会拒掉它，返回的是**单独一句体感话术**（"这个地址走的是不加密的通道，我不开"，就近在 `sources.py`、不进 corpus）——不是"（这个地址我不去）"，免得听起来像在拒绝对方（拍板 #17）。
- **残余"编 URL"口子**：回忆信号触发的轮里 `specs()` 仍含 `open_link`，而上下文里一条合法 URL 都没有——模型硬编一个的概率低（`desc` 已改成"别人给了我一个地址"），且有**预算 + SSRF + 摘要层三重兜底**，可接受。从根上关的进程内旗见拍板 #18（**本批不实现**）。
- **`open_link` 可见性依赖 `sources.py` 被 import**：工具是 `sources.py` 向 `tools` 注册的，所以引擎启动时必须先 import 过 `sources`（本批在 `core.py` 顶部 `import sources` 保证；见 §4 记账 #7）。
- **闸门 2 粒度粗**：可能把当轮注入的条目全补进素材，即使用户追问的**根本不是刷到的东西**（`EXPAND_QUERY` 是通用追问词）——量级有界（每天 ≤ `BROWSE_CONTEXT_MAX`），**别在实测时当 bug 查**。
- **闸门 3 盲区**：`daily_review` 在"今天还没怎么聊"时早退（`diary.py:82-83`）——**纯浏览、没对话的日子，刷到的东西永不过闸门 3，90 天后直接清掉**。这符合"人味闸门"设计（没聊过 = 不重要），但要知道。
- **闸门 3 每天 ≤ 1 条**：刷到十条也只可能沉淀一条——刻意为之（§6.3 保召回排序）。
- **（小）注入与补素材之间有错位窗口**：`build_chat_messages` 与闸门 2 两次查 `items_today`，其间后台刷信息线程可能新增一条，导致"补的"与"注入的"错位一条——单用户自用可接受。
- **`open_link` 可被诱导弹内网**：防线只有主机名黑名单；若将来对外服务，必须回到拍板 #4 重新评估。
