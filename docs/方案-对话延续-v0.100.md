## 0. 诊断 —— 三个断点，外加一个当场卡死的 P0 bug

证据全部取自 **2026-10-16 服务器 `friend.db`**（消息 id 与 kv 原值），不是推测。

### 0.1 【P0 bug】游戏模式没有出口，主动消息被**永久**封死

```
kv.game_state = {"game": "soup", "started_at": "2026-10-16T22:36:57"}   # 查库时仍未清
```

- `game.py:44 current()` 只读 kv，**没有任何超时/过期**；退出只认 `corpus.GAME_STOP_WORDS`（"不玩了/结束游戏"…），用户当天一句没说 → 状态一直挂着。
- `guard.py:69-72`：`if game.current(): return False, "游戏中"` —— **游戏进行中拦截一切主动消息**，且这条在 `guard_enabled()` 短路**之前**，guard 关着也拦。
- 后果：**从 22:36 起该朋友再也发不出任何主动消息**（早安/午间/晚安/随机闲聊/冒泡/轻催/承诺提醒全灭）。
- 附带：游戏 **22:36 才开局**——触发词要求**用户**亲口说出游戏名（`game.py:69 detect_start`），而"海龟汤"这个名字是 TA 先提的。所以 22:08–22:35 整段是**裸跑、规则没注入**；开局那次还是用户 22:36 抱怨句里的"海龟汤的规则你也不懂"撞上的。

> 这一条独立于用户的诉求，**必须先修**：不修，批 2/批 3 做完也发不出消息。

### 0.2 无时间点的承诺**只进记忆、不进队列**

好的一面：这句承诺**确实被记下来了**，当天 `memories` 里两条（`created_at` 2026-10-16）：

```
计划 | 我说这就去翻原文，翻到就一段一段贴给小徐（小徐还没看到这条）
计划 | 我打算回头翻出《雾都孤儿》那两页原文贴给小徐，小徐说"可以呀"
```

坏的一面：它只是一条**记忆**，不是**一件待办**。现存三条"承诺"通道都接不住它：

| 通道 | 落点 | 为什么接不住 |
| --- | --- | --- |
| `events.add_care` | `events.py:47-56` | **必须有具体时刻**（`when` 是未来绝对时间，`memory.py:54-61` 的 prompt 也这么要求）。"回头翻到就贴"没有时刻 → 直接不收 |
| `todos` 待办 | `todos.py:7-13` | 入队只有两个来源：读书素材、内心独白【我自己的话题】。**对话里冒出来的承诺不进** |
| `selfmem.self_promise` | `selfmem.py:283-290` | 要等**睡前复盘**（一天一次 LLM）才可能抽出；且只当"下次开口的弹药"，在六源里**优先级最低**（`context.py:263-272`） |

一句话：**带时间点的承诺有闹钟，不带时间点的承诺掉进黑洞**——记着了，但没有"该我兑现了"的触发。

### 0.3 海龟汤规则只写了"你当出题人"

- `game.py:29-39` 的 `soup.rules` 通篇是**出题人视角**（"你先选定一个完整的海龟汤故事…只告诉TA汤面…TA猜出真相就揭晓"），**没有一句**写"当你当猜方时该做什么"。
- 当天用户是出题人、TA 是猜方（`id 1112` "我也考你一个噢"），于是 prompt 里没有"该我每轮问一个是/否问题"这条作业。
- 现场：`id 1116` 汤面 → `id 1117` TA 只回一句"哈，这题开场就见血，够狠😏"就停；用户 `id 1118` "来吧！"催了一下，TA 才在 `id 1119` 问出第一个问题。**"你不触发它就不问"就是这么来的**。
- 叠加 0.1：就算它想问，游戏进行中 guard 也把一切主动消息拦死了——**TA 没有任何自主开口的通道**。

### 0.4 归纳：TA 现在只有两种开口方式

1. **回应**：用户说话 → `core._generate_reply` 回一次（可分段）。**一问一答，一轮一次，不可能连问。**
2. **定时主动**：`scheduler.py` 的六个 scenario —— `morning` / `noon` / `night` / `random`(每小时 20% 骰子) / `bubble` / `nudge`。
   - 其中**唯一**能接住"半截对话"的是 `nudge`（`core.py:581-601`）：会话开着 + 空闲 10–20 分 + 60% 概率，内容只是 `persona.py:325` 的"人咧？/去忙啦？"。它是**通用催**，不是"把这件事接着说下去"。
   - `nudge` 还会被 0.1 的游戏拦截吃掉。

**根因一句话**：TA 的话语权来自**定时器与骰子**，从来不来自"**我欠你一句话**"。所以任何"需要跨轮延续"的东西（游戏的一问一答、答应的后续）都无处安放。

## 2. 分批（按依赖排序，批 1 先行）

### 批 1 —— 修 P0 卡死（**必做，最小**）

- `game.py`：`start()` 写 `last_active`；`current()` 在 `now - last_active > config.GAME_IDLE_MINUTES` 时自清（顺手 `stop()` 写回空值，别留脏数据）并返回 `None`。
- **刷新口径**：游戏进行中收到**任何**用户消息都刷新 `last_active`（`core.on_user_message` 里 `game.on_user_text` 一处改即可）——**不判"是不是在说游戏"**：TA 的回复都由用户消息触发（游戏期间主动消息被拦），"用户还在说话"就等于"对话还活着"，语义判定不值当。
- **存量数据兜底**：旧 `game_state` 没有 `last_active` 字段的，用 `started_at` 兜底算空闲（服务器那条已手清，但本地 / 其他朋友库可能还挂着旧值）。
- **过期自清顺手入队（新）**：`current()` 判过期时 `todos.add("上次{label}玩到一半没玩完，找机会问问TA还玩不玩", source="game")`（`TODOS_ENABLED` 开着才入；`todos.add` 指纹去重天然幂等）——"没玩完的话头"直接进既有待办队列，下次主动开口自然续上。**这是批 4「通用未完成话头」在游戏域的最小特例，零新基建**（入队 / 注入 / 打勾链全是现成的）。
- `config.py` + `tuning.py`：新增 `GAME_IDLE_MINUTES`（默认 45，**双头维护**）。
- **本批不做**：不做游戏内的续玩主动消息（留给批 3）；不改 `corpus.GAME_STOP_WORDS`。
- 用例：`test_life.py`（游戏域现有用例所在文件）加两条——①开局后把 `last_active` 拨回 1 小时前 → `current()` 返回 `None` → `guard.can_send_proactive` 恢复 `ok`，且待办队列出现"没玩完"那条；②存量无 `last_active` 的旧状态同样过期。

### 批 2 —— 无时间点的承诺入队

- `EXTRACT_PROMPT` care 段（`memory.py:54-61`）补一句：承诺没有具体时间的（"回头 / 待会儿 / 晚点 / 改天"）照加 `care`，但 `when` 留空字符串。
- `memory.py:254-263`：`care` 有 `when` → 照旧走 `events.add_care`；**没有 `when`** → `todos.add(care["what"], source="promise")`。
- **裸文本入队（修订）**：入队存**原文**，前缀"（我答应过TA：…）"只在**注入渲染时**加（`todos.prompt_hint` + `context` 待办源两处按 `source` 渲染）——若把前缀直接存进条目，`todos._hit` / `mark_done` 的字面指纹永远匹配不上前缀，打勾失灵。
- **源内优先**：`source="promise"` 的条目排在普通待办之前取（"欠别人的" > "想分享的"）——一行排序键，不改六源结构（原 P3 的"提到待办之前"落到这里：进了 todos 就是同一源，顺序是源内的事）。
- **复用 todos 三机制白拿（强化 P2 论据）**：① id 携带打勾链（`context._carry` → `todos.mark_done_by_id` → `core._settle_carried_ids`）②指纹去重防重复入队 ③`pending()` 注入——新建 `followups` 表这三处全要重写。
- ⚠️ 与既有 `memory.py:147` 的**承诺时序安全网**（`assistant_tail=True` 时丢弃"答应/承诺/保证"类记忆）对齐口径：那条防的是**错位归因**（把用户没回应的提议记成"我答应"），不能因为新增通道绕过去——**`assistant_tail=True` 时 todos 通道一并跳过**，两通道一视同仁。
- **本批不做**：不新增 `followups` 表；不改 `EXTRACT_PROMPT` 的 care 段措辞之外的部分。
- 用例：`test_memory.py` 加一条——喂"我答应回头翻原文贴给你"且用户回应过 → 断言 `todos.pending()` 出现**裸文本**该条（无前缀）、且 `events` 里**没有**新建 care 事件；`test_proactive.py` 加一条断言 promise 条目排在普通待办之前。

### 批 3 —— 海龟汤猜方规则 + 游戏内续玩通道

- `game.py` `soup.rules`：补猜方一段（P4 推荐）：对方考你时，你的活儿是**每轮只问一个"是/否"问题，问完就停、等对方回答**，别一次问一串、别自问自答、别急着下结论。同一段点明"**角色可以互换**，谁出题谁答'是/不是'"，把现有"如果TA想换你猜，也可以换角色"展开成可执行的作业。
- **guard 给游戏开一个口子（新）**：`guard.py:69-72` 的"游戏中全拦"改为**拦闲聊不拦 nudge**（`scenario == "nudge"` 放行）。§6 原"未核实是否有意为之"已销——`game.py` 模块头注释（第 8 行）写明是**有意设计**；本批是给这个设计开例外，不是修 bug。
- **nudge 游戏感知（新）**：`game.current()` 非空时，nudge 的场景 prompt（`persona.py:325`）注入游戏规则 + "该你了，接着玩"——**TA 在游戏里获得自主开口通道**，正是用户抱怨"没有我的触发就不问"的直接解。nudge 本来就是 LLM 生成（那句"人咧？"是 prompt 指令不是固定文案），改动 = guard 一行 + persona 一个分支。
- **时序正好咬合**：nudge 窗口（空闲 10–20 分钟）< 游戏过期（45 分钟）——TA 先在游戏活着时有开口机会，过期了才走批 1 的"没玩完话头"入队。
- **本批不做**：不做"轮到谁"的状态机（批 4 之后评估）。
- 用例：①断言 `game.prompt_injection()` 在 `soup` 下包含"是/否""每轮只问一个"等关键词（防回退）；②`guard.can_send_proactive(scenario="nudge")` 游戏中放行、`scenario="random"` 仍拦。

### 批 4（**暂缓**，等批 1–3 跑一周再评）—— 通用"未完成话头"事件源

把"对话里没说完的话头"做成第一类公民，与 `events`(care) 并列：**没有具体时间，只有软到期**。

- 每轮回复后判定"我有没有留半截话 / 对方在等我下一句" → 登记。
- 到期（当晚/次日）由 TA 自己接上。
- **批 1 已把它的游戏域特例做了**：游戏过期 → "没玩完"入队，就是"未完成话头"在游戏域的最小实现；批 4 剩下的是非游戏域的**通用判定**（怎么识别"我留了半截话"），语义识别才是它贵的地方，仍暂缓。
- **为什么暂缓**：它和 `nudge`（通用催）、`todos`（想说没说）、`care`（定时承诺）三处语义重叠，去重口径没拍清就上线，会出现同一条话头被催两遍。收益是否值得，看批 2 把"承诺"接住之后还剩多少缺口。
