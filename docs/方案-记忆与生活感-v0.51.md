# 方案：今日上下文 + 艾宾浩斯记忆衰减（v0.51）

> 2026-10-10，源自用户提议：「一天所有信息交流都要进入记忆，规则还是 AB 库，像阅读内容就存放在 B 库，然后注入上下文，直到写日记的时候才从上下文中清除，记忆还是保留；再加一个需求——记忆按艾宾浩斯遗忘，遗忘过程就是一次次对某条记忆总结的过程，当总结达到一定次数就彻底遗忘删除，重复调用会让记忆保持当前状态时间变长，当达到一定次数就永久记住」。

---

## 一、问题：不是「记得不够多」，是「不知道自己今天在干嘛」

新抽的朋友（星仔）遇到两个现象：

1. 问「你今天都做了什么」答不上来 —— 工作内容只在 **忙/心流相位** 注入（`work.prompt_hint`），其它时候问就是两眼一抹黑；
2. 不会主动聊自己读到的东西 —— 素材只在 `random` 主动场景里一半概率翻一次。

所以要做的&#x662F;**「今天发生了什么」这件事有据可查、随时能说**，而不是把全部对话塞进上下文。

---

## 二、方案 A：今天的事进 B 库 → 注入当天上下文 → 跨天自然消失

### 写：复用 B 库（`long_memories`），不新建表

工作单元结算产出素材时（**不额外调 LLM**，素材文本已经生成好了），顺手落一条 B 库记录：

| 字段           | 内容                                      |
| ------------ | --------------------------------------- |
| `summary`    | `今天读到《{title}》第 N 段` / 泛化时：`今天忙完第 N 件事` |
| `content`    | 金句摘抄 + 读后感原文（+ 段落正文节选，截断 1000 字）        |
| `category`   | 事件                                      |
| `tags`       | `今日素材`（识别标记）                            |
| `time_label` | 今天日期                                    |

写入点：`work._gen_shareable()` 成功返回文本后。

### 读 + 注入

- `memory.today_notes(day)`：B 库里 `tags` 含「今日素材」且 `created_at` 是**今天**的条目，最新 3 条，正文每条截断 200 字。
- `context.build_chat_messages`：在「相关记忆」**之前**插一条 system：


  ```
  【你今天做过的事】（只限今天，跨天就记不清细节了）
  - 今天读到《XX》第 3 段：「……」（你的感想：……）
  ```
- **跨天自动不再注入**：筛选条件就是「今天」——写完日记、睡一觉，第二天这条注入自然消失，而 B 库里的记录**保留**（这就是用户要的「从上下文中清除，记忆还是保留」）。

### 为什么不做「全部对话常驻上下文」

- `messages` 表本来就是全量记录（一天所有交流都在里面），真需要靠 `recall` 拿，不必常驻；
- 常驻会让每条消息的 prompt token 翻几倍，还会**稀释**重点（记忆/便签/人设被淹没）。

---

## 三、方案 B：艾宾浩斯衰减 —— 遗忘 = 一次次总结

### 数据：A 库 `memories` 加两列（带旧库迁移）

| 列             | 含义                                     |
| ------------- | -------------------------------------- |
| `decay_level` | 0=原文；1=压缩过一次；2=再压一次；≥MAX=彻底遗忘（删行）。默认 0 |
| `pinned`      | 1=永久记住，永不衰减。默认 0                       |

B 库长文**不单独分级衰减**——它是原文证据（书摘/长对话），只在它挂着的 A 库记忆被删除时一起删。

### 规则（三个数决定一条记忆的命运）

1. **什么时候该遗忘**：以 `recalled_at`（最近一次被想起）为准，没被想起过就用 `created_at`。  
   `有效期 = DECAY_IDLE_DAYS × (1 + recall_count × DECAY_RECALL_BONUS)`  
   → 被想起的次数越多，有效期越长。**这就是「重复调用会让它保持当前状态更久」**。
2. **遗忘一次 = 总结一次**：到期 → `decay_level += 1`，用 LLM 把这条压成更短的一句（L1 约 50 字、L2 约 20 字）。
3. **压到 MAX 就删**：`decay_level ≥ DECAY_MAX_LEVEL` → 删除 A 库行 + 连带删它的 B 库长文 + 向量。  
   `recall_count ≥ DECAY_PIN_RECALLS` → `pinned=1`，**永久记住**，永不参与衰减。

默认值：`IDLE_DAYS=30`、`RECALL_BONUS=0.5`（想起 4 次 → 有效期 90 天）、`MAX_LEVEL=3`、`PIN_RECALLS=8`、`BATCH=6`（一天最多压 6 条）。

### 执行时机：挂在睡前复盘里，一天一次，不另起进程

`diary.daily_review()` 结尾调 `memory.forget_pass()`：**一次** LLM 调用批量压缩全部待衰减项（不多调）。  
LLM 不可用 → 本次跳过，下次再试。手动也能跑：`/forget`（`/forget dry` 只预览不动手）。

### 防走样：宁可不衰减，也不让记忆变味

总结提示词硬性约束「只允许压缩、不允许新增细节；不确定就原样保留」，落库前过三道校验：

- 长度必须 **≤ 原文**（变长了就是模型在编）；
- 过 `_validate` 红线（推测/元信息/失忆类一律丢弃这次结果）；
- 结果 ≥ 6 字、且不能直接套用原文。

校验不过 → **跳过这条，下次再说**（保真优先于衰减）。

---

## 四、验收（测试）

- `test_today_notes_injection`：工作产出素材 → B 库有「今日素材」→ `build_chat_messages` 里出现注入；跨天的不出现。
- `test_memory_decay`：① 到期且 LLM 压缩成功 → level+1、内容变短；② recall_count 高 → 有效期变长（不被判到期）；③ ≥ PIN 次数 → pinned 不衰减；④ 压到 MAX → 删行 + 连删 B 库长文；⑤ 模型返回比原文更长 → 跳过不改写（保真）。

## 五、明确不做（边界）

- 不做「全量对话常驻上下文」（见上）；
- 不做独立遗忘进程/定时器（挂日记复盘，一天一次，省调用）；
- B 库长文不参与分级压缩（它是证据，不是记忆本体）；
- 稳定 profile 字段 / 事实便签（`facts`）不参与衰减——那是身份级事实，遗忘会伤人。
