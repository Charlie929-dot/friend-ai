### v0.101（2026-10-16）—— 第三批：模型下拉 + 正在输入气泡（web 两修）

| # | 类型 | 问题 | 修复 |

| 2 | 🐛 bug | **聊天区没有「正在输入」**：唯一提示是右侧「此刻的 TA」抽屉里的一行小字；CSS 里 `.typing-bubble`（三个跳动小点）写了却**从没接过线**。另：`typing_now()` 叠了个硬编码 **+8 秒**假窗口 → 回复已经到了气泡还挂着几秒（[实测 #52](./实测反馈/#52-模型下拉与正在输入气泡.md)） | ①把 `.typing-bubble` 接进聊天流（`setTypingBubble`，永远吊在消息流最末，不占左侧目录、不进消息表、不可引用）；②`WebChannel` 不再覆写 `typing()`、`typing_now()` 只读 `generating`——core 的 `set_generating` 本来就覆盖「进入回复流程 → 全部段落发完」全程（v0.75 的设计），那个 +8 秒是旧实现的残留，删掉即无残影 |

| 2 | 🐛 bug | **主动消息分段零停顿**：LLM 用换行并成一条的回复拆段后同一秒全部拍出，无打字节奏 | `_proactive` 分段循环复用正常回复的 `SEND_*` 段间隔（按下一条长度，`core.py` 与 `_generate_reply` 同一套口径） |

| 4 | ✨ 体验 | **日间休息不看精力**：精力数值/早睡熬夜/疲惫心情/打断疲劳都已有，唯独休息时长只按「刚读完那段长度 × 0.3」，累不累不影响歇多久 | **精力歇点**：`life._make_sessions` 排班时预演精力（与 `energy()` 同一套率），读完这段精力 < `WORK_ENERGY_REST_BELOW`（默认 40，新参数）→ 那次休息延长到「再读一整段也不破线」再开工。预演在 wake 排定时做，不动「当日只读、数字派生」哲学；歇穿到睡前也认（太累 = 今天早点忙完，不追进度） |

新用例 `test_proactive_guard_and_energy_rest`（test_life）+ `test_proactive_pacing_and_stream`（test_proactive），`EXPECTED_TOTAL` 87 → **89**，全量 89/89。连带修两个「与真实作息耦合」的既有测试（`test_game_mode` / `test_bubble_fixed_corpus` 补 `WORK_ENABLED=False`，约定 #10）。
