## 一、版本记录（v0.2 – v0.26，更早的已不可考）

> v0.26（2026-10-08）：一视同仁·认知层语义改造（先小步，schema 待做）——①记忆提取 prompt 从"只记用户事实+不记我自己"改成"记对我自己有趣/重要/相关的事（自己+对方+关系）"，红线从"不记我说的话"改为"不记我对对方的客套评价、但我自己的偏好/计划/想法要记"；②日记 prompt 从"复盘今天和{user}的聊天/写和{user}相处的一天"改成"复盘自己今天/写我自己的一天"；③措辞中性化「用户→对方/TA」：COMMON_RULES、PROACTIVE_SCENARIOS、build_proactive_prompt、记忆检索工具 description、\_format_convo 结构化标注、corpus.META 正则（加"对方"分支）。schema 层（memories 加 subject 列 + profile 改 profiles 多对象表）已记入需求池「多对象一视同仁」待做。测试 36 项全过
>
> v0.25（2026-10-08）：①"名字无优先级"从宗旨降级为需求——移出关键决策表、新增需求池「名字系统重构（名字多面共存）」条目（现状：friend_name 单值+优先级、\_archive_display 与 \_friend_name_in 优先级不一致）；MEMORY.md 宗旨只留"一视同仁"并扩写（记忆/日记/称呼都不围绕用户特殊化）。②定位名字污染源头（定论）：污染值 {"name":"小葵","label":"温柔治愈",...} 是测试夹具硬编码串（test_p1_features.py:545，commit effacc0 引入），非 persona_pool.draw() 产物（小葵属"阳光话痨"、温柔治愈骨架无小葵，组合非法）；迁移备份证明 51fa84ad 在 10-06 12:15 迁移时干净，污染发生在迁移后、由未隔离的 config.DB_PATH 写入。③"一视同仁"代码审计完成（记忆提取/日记/人设 prompt 多处用户视角），修改方案待与用户讨论
>
> v0.24（2026-10-08）：修"名字错乱"bug + 确立两条宗旨。①bug：初遇朋友（friend-51fa84ad.db）的 persona_json 被历史污染成"小葵"（早期测试硬编码字符串遗留），切到它时 AI 自称"小葵"、CLI 也显示"小葵"，与别名"初遇朋友"冲突、两个名字打架。修复（纯数据）：清掉污染 persona_json（初遇朋友是独立朋友、无人格卡），别名"初遇朋友"→"初遇"；初遇/小葵现在是两个独立朋友、名字各自正确。②确立两条宗旨（用户定）：**名字无优先级**——一个 AI friend 的名字多面共存（原名 persona 卡名=别人叫 / 别名=用户私下叫），都是 TA 自己的名字、平等共存不互相覆盖，不搞优先级之争；**一视同仁**——AI friend 不知道"用户"这个特殊身份，平等对待所有其他人（包括用户），设计不围绕用户特殊化
>
> v0.23（2026-10-08）：修工具观踩线（方案1）——长文标记保留机器可读"长文"契约词：`_TOOL_LONG_MARK`="【还有长文，可以再回想一下】"（原"【还记得更细…】"把"长文"契约词拟人化掉了）、`_TOOL_DETAIL_DESC` 引用同步为"标了【还有长文】"，前后一致、AI 能找到触发 recall_detail 的标记。测试 36 项全过
>
> v0.22（2026-10-08）：工具观补"两层分离"守则 + 自我审查归并——①回答"工具观会不会导致工具调用失败"：体感拟人（外壳）不得牺牲契约（内核），function calling 的"何时调/调哪个/参数/返回"必须保留清晰；已发现一处踩线：`_TOOL_LONG_MARK` 拟人化成"【还记得更细…】"但 `_TOOL_DETAIL_DESC` 仍引用"标了【有长文】"，前后对不上、可能让 AI 找不到触发 recall_detail 的标记（代码待修、未动）。②"定期审查 profile"与"对话双线（审查线）"不重叠但都叫"审查"易混——归并进「自我审查」大类：对话线审查（实时审回复）/ 定期审查 profile（周期审字段）/ 记忆修正（每日回顾已做），对象、频率、时机各不相同
>
> v0.21（2026-10-08）：用户称呼动态化——确立"称呼来自 profile、不写死"约定：AI 对用户的称呼 = 每个朋友自己 profile 里的"称呼"字段（事实便签"叫我X" > profile 称呼 > config.USER_NAME 兜底），**不同朋友可有个性称呼**（小葵叫小徐、稳稳叫徐哥）。新增 persona.user_name() 统一读取；groupchat/memory/diary 里硬编码"小徐"全部改为动态读取（群聊发言时 db 已切到对应朋友，自动取 TA 的称呼）；config.USER_NAME 只作兜底默认。测试 36 项全过
>
> v0.20（2026-10-08）：工具拟人化落地——确立"工具 = AI 身体组分"约定（用户定）：AI friend 没有"工具"，只有"能力/器官"，记忆检索 = 大脑在回忆、行为接口 = 自己的作息意愿。memory.py 两个检索工具的描述/参数/返回全部改拟人化："这是你的记忆，你可以随时回想…"、"想起来了：…"/"（回忆不起来了）"、"你想回想的事，用你自己的话说出来"，不出现"搜索/检索/数据库/工具"类词。此约定同时统一到「AI 自主行为接口（MCP）」——未来睡眠/冒泡/状态等行为接口同样用"我想睡了/我醒了"的能力口吻，而非"设置状态"。测试 36 项全过
>
> v0.19（2026-10-08）：记忆检索"快速止血"落地——①search_memories / recall_detail 加 source 参数（private/group/all），用户说"群聊"时 AI 可指定只搜群聊记忆，recall 按来源过滤、group 记忆全量参与不再受"最近 5 条"限制；②工具 query 参数描述引导"把口语问法重写成检索关键词"（意图重写）；③召回为空时工具返回直接做成"（记不清了）"的大脑反馈（用户改进：贴合真人"想不起来"的体感、比 prompt 里加规则更直接）。测试 36 项全过
>
> v0.18（2026-10-08）：①修"群聊四个人四个时间"——persona.build_system_prompt 增加 now/life_wake_hour 参数，群聊每轮（回应/闲聊）刷新一个统一时钟 s.now，所有朋友共用同一钟表时间 + 统一生活日参照 config.WAKE_HOUR（不再各自 wake_hour），私聊行为不变；②记忆调度"深度思考"问题分析入池——用户指认"目前最大问题"：召回纯字面 bigram、群聊记忆私聊召不回、AI 不懂"早上的群聊"要专门搜群聊来源、检索空集被当绝对事实。定位四层根因 + 四层方案，代码未动等确认
>
> v0.17（2026-10-08）：群聊五大需求入池（仅讨论方案、未动代码）——①闲聊常态化：从"冷场才触发一轮突发"升级为"持续背景流 + 记忆驱动话题"（聊记忆里的事，而非被 IDLE_HINT 提示"随便聊你的生活"），用户插话即让位、消化完自然恢复；②时间统一：修"四个人四个时间"（钟表时间被各自"生活日"改写 + 每句重取 now 漂移），统一时钟单一来源、钟表时间/生活日分离，长期挂 MCP get_time；③群聊命名 + 多群独立 + 按群查看 + 实时记录（群名可选/默认、\_session 单例改多群、group_transcript 表随聊随存）；④主动系统新增"群聊提及"触发源——群聊@我/提到我，朋友私聊告知发生了什么；⑤载体方向：鸿蒙原生 App（用户用鸿蒙，群聊概念与企业微信组织架构群冲突），通道层抽象+适配器，企业微信备案暂缓
>
> v0.16（2026-10-07）：语料定义澄清（用户指正）——corpus 只装「会扩充」的两类：①固定回复语 ②匹配用户话的关键词/正则；「不会扩充」的固定文案（MCP 工具 description、工具返回固定句）不属语料、回到 memory 就近维护。匹配正则统一收进 corpus（身份询问/追问细节/回忆信号 + 提取红线 SPECULATION/META/PROMISE/SELF_AMNESIA/MEMORY_QUIZ/MEMORY_REMINDER + 停用字/相对时间词），groupchat 的 HANDOFF_SIGNALS、guard 的 BUSY_SIGNALS 一并归位  
> v0.15（2026-10-07）：记忆主动检索（function calling）——AI 在对话里自己决定何时查记忆、查什么。回忆/追问信号下带工具调 LLM，AI 主动调 search_memories（查 A 库摘要）/ recall_detail（展开 B 库全文），程序执行工具回填结果，最多 3 轮；普通聊天走快速路径省 token。llm.chat_with_tools + memory.MEMORY_TOOLS + core 工具循环  
> v0.14（2026-10-07）：A/B 两级记忆库落地——B 库（long_memories 表）专存长文本（一句两句说不完的），每条配摘要；A 库（memories）记忆带 long_id 伪链接，召回默认只给摘要，追问细节（"详细讲讲"）时才展开全文注入。提取器识别长文分流（long+full 字段），db 层新增 long_memories 表 + 存取函数，context 渲染长文标记 + 展开全文  
> v0.13（2026-10-07）：记忆架构澄清（用户细化）——①"临时系统提示词"注入机制确认已落地（独立于常驻人设、独立于上下文、随每轮 query 变化）；②A 库（概要/短内容）/B 库（长文本，伪链接跳转）两级记忆设计细化；③MCP 主动检索细化（反复被要求回忆时 AI 自己调工具检索 A 库）
