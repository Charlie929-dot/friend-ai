# 文件改动同步清单（改了哪个文件 → 要同步哪里）

> **📋 本文档职责**：改了哪个文件 → 要同步哪里（逐行查，表尾有通用规则）。
> **🚫 不管**：工作流 / 硬性约定 → [AGENTS.md](../AGENTS.md)；需求池状态 → [需求概要-朋友型AI.md](./需求概要-朋友型AI.md)。
> **⏰ 必须更新**：新增常改文件时补行；表里没有的文件按通用规则处理并补行。

> 配套 [AGENTS.md](../AGENTS.md)「一、改完并测试完代码必做」：每改完一个文件，按下表把该同步的地方同步掉——**只改代码不同步 = 改动没做完**。
> **表里没有的文件**：按文末「通用规则」处理，并顺手给本表补一行（本表的目标是覆盖所有常改文件）。
> 相关硬性约定（语料只装会扩充的 / 称呼不写死 / 代价只呈现不归因 / 内部 prompt 不拼完整人设 / 测试解耦 / 打勾纪律…）见 [AGENTS.md](../AGENTS.md) 第三节。

## 通用规则（表里没有的文件 / 什么改动都逃不掉的）

1. **跑测试**：改完跑全量 `.venv/Scripts/python.exe run_tests.py`；新用例写进对应 `test_*.py` 即自动被收集（v0.92 起，不再是手写 `__main__` 列表）。
2. **新模块/新文件**：需求池对应模块加条目 + 版本更新记录写一条 + **本表补一行**。
3. **新配置项**：`config.py` 默认值 + `.env.example` + `/refresh` 热重载验证。
4. **prompt/文案**：过三条红线——工具拟人化的契约词别改（约定 #2）、代价只呈现不归因（#5）、生活三源没有身体（persona 行）。
5. **表结构**：加列带旧库迁移（db 行），别破坏旧库。
6. **提交推送 + 同步服务器**：`git add -A && git commit && git push origin main`（中文 message 一句说清）→ `source ~/.bash_profile && bash sync-to-server.sh`（自检 HEAD + `GET /login` 200）。
7. **`.workbuddy/memory/YYYY-MM-DD.md`**：append 一条工作日志（做了什么、结论）。
8. **文档单一事实源**：踩坑细节唯一真相 = 实测编号；版本记录只写"做了什么"；需求池只记状态。别处放链接、别把同一段话复制粘贴到多个文档。
