# 朋友型 AI · 需求概要 v0.29

> 一个**自己专属**的朋友型 AI，核心特征是**主动**——它不等指令，而是有自己的作息、工作、记忆和生活节奏。
> **一句话价值主张**：让 AI 从"随叫随到的工具"变成"有自己生活的伙伴"。
> 📦 历史部分已拆出：**v0.2–v0.26 版本记录 + 实测反馈 #1–#15 全文 → [历史归档-版本与实测.md](./历史归档-版本与实测.md)**

> v0.29（2026-10-09）：**文档重构为模块化精简版**。①需求池从"按优先级排一条长龙"改成**按 8 个能力模块归类**，每条标注「阶段 + 必要性 + 状态」；②重排阶段 P0–P3 → **S1–S5**（能聊 / 像人 / 有自己的生活 / 越来越懂你 / 底线与边界），把已完成项从"待做"里摘出来；③对每条功能做必要性判定，**砍掉 5 条、降级 5 条、留 3 条待你拍板**，理由见「四、必要性判定」；④历史版本记录与实测反馈全文移入归档文件，主文档只留索引。
> v0.28（2026-10-09）：吸收外部参考《朋友型 AI · 关键机制设计详解》（三大机制 + 合规红线），逐条比对后入池——新增 4 条：**打断成本机制（含状态 HUD）**、**主动分享内容生成**、**事件记忆与关怀触发**、**合规红线**（原文档完全缺失的一块）；升级财富（**"钱"拍板纯叙事、绝不绑真实付费**）与工作（工作循环 + 心流期）。并按宗旨校正：参考材料通篇"围绕用户"（用户事件记忆/用户兴趣模型/用户最在意被记得），本项目改口径为 **TA 记下的、和对方有关的事**，关怀的正当性是"朋友本来就会关心朋友"、事后追问是 **TA 自己好奇那件事后来怎样了**，功能照搬、**主语不照搬**；"成本可见但不指责"升为红线，禁止代价归因措辞；"破茧注入"升为必做（人格独立的证明）。
> v0.27（2026-10-09）：移除群聊·回归单人版（用户拍板"只保留最初愿望"）。删 groupchat.py 及全部群聊代码与配置；记忆系统回单一私聊来源。多对象版存 git 分支 multi-object 留档。测试 21 项全过

> **进度**：S1 能聊 ✅ 收官（10-05）；S2 像人 ✅ 收官（10-08）。**S3 有自己的生活 = 当前主线**。S4/S5 待启动。

## 一、产品定位与项目约定

| 维度       | 结论                                                                                                                              |
| -------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 目标用户     | 自己专属（单用户，深度个性化）                                                                                                                 |
| 载体形态     | 接入现有 IM（企业微信自建应用）；鸿蒙原生 App 为备选，见待确认 #7                                                                                          |
| 模型/运行    | 云端 API（DeepSeek）+ 云服务器 7×24                                                                                                      |
| **一视同仁** | **项目宗旨**：AI friend 是独立个体，不知道"用户/主人"这种特殊身份，平等对待所有其他人（包括你）。记忆、日记、称呼都不围绕你特殊化——TA 记的是对自己有趣/重要/相关的事，日记是 TA 自己的生活                    |
| 工具观      | 工具不是外部 API，是 TA 自己的"身体组分"（记忆检索=大脑回忆、行为接口=作息意愿）。**两层分离**：拟人化只管体感外壳，function calling 的契约内核（何时调/调哪个/参数/返回结构/标记 token）必须清晰         |
| 用户称呼     | 称呼来自每个朋友自己的 profile（事实便签"叫我X" > profile 称呼 > config.USER_NAME 兜底），不同朋友可有个性称呼，代码不写死                                               |

## 二、模块地图

### 2.1 模块划分

需求池不再按优先级排长龙，改按**能力域**分成 8 个模块（A–H）。模块是稳定的，阶段是推进节奏。

| 模块              | 一句话               | 覆盖阶段    |
| --------------- | ----------------- | ------- |
| **A 人格与身份**     | 它是谁               | S2 → S4 |
| **B 记忆**        | 它记得什么             | S2 → S4 |
| **C 主动** ★      | 它主动找你（产品核心）       | S1 → S4 |
| **D 生活**        | 它自己的日子（作息/工作/被打断） | S1 → S3 |
| **E 对话与互动**     | 它怎么说话、和你一起玩什么     | S2 → S3 |
| **F 自主**        | 它自己掌控自己           | S2 → S4 |
| **G 载体与工程**     | 跑在哪、怎么运维          | S1 → S2 |
| **H 合规与安全**     | 底线（不产生功能价值，但必须守）  | S3 → S5 |

### 2.2 阶段推进节奏

原 P0–P3 已混乱（P2 里混着已完成项、P3 里混着重要项），重排为 S1–S5：

| 阶段              | 主题        | 主线模块      | 状态         |
| --------------- | --------- | --------- | ---------- |
| **S1 能聊**       | 先跑起来      | C + D + G | ✅ 已收官      |
| **S2 像人**       | 说话像、记得住   | A + B + E | ✅ 已收官      |
| **S3 有自己的生活**   | 它有边界、有日子过 | D + E + H | 🔵 **当前主线** |
| **S4 越来越懂你**    | 召回准、会关心   | B + C + F | ⚪ 待启动      |
| **S5 底线与边界**    | 合规护栏      | H         | ⚪ 待启动      |

**必要性分级**：核心（没有它产品不成立）/ 增强（显著提升"像人"的程度）/ 可选（锦上添花）/ 不做（本轮砍掉，理由见第四节）。

## 三、需求池（按模块）

### A 人格与身份 —— 它是谁

| 需求             | 阶段  | 必要性  | 状态    | 说明                                                       |
| -------------- | --- | ---- | ----- | -------------------------------------------------------- |
| 人格池系统          | S2  | 核心   | ✅     | 6 骨架 × 随机名 × 随机怪癖（180 组合），/new-friend 开盲盒且不可重摇——"没得选才是朋友" |
| 初识系统           | S2  | 核心   | ✅     | 关系阶段 new/familiar；初见期不查户口、按氛围追问；信息清单按朋友隔离（新朋友零了解开局）     |
| profile 自动维护   | S2  | 核心   | ✅     | 提取器把确定性事实（称呼/生日/城市等）写进清单；用户手填的字段不覆盖                      |
| profile 定期审查   | S4  | 增强   | 待做    | 每日回顾时审一遍字段，发现错误/新信息就修正。属「自我审查」大类                         |
| 名字多面共存         | —   | 可选   | ⚠️ 待拍板 | 原名（persona 卡名）+ 别名（你私下叫）平等共存、不互相覆盖。当前单值能跑，重构名字层成本高      |
| 人格体系 v2        | —   | 可选   | ⚠️ 待拍板 | 百分比性格调料 / MBTI 等细致化。先调研；除非实测发现人格不够鲜明，否则 6 骨架 + 怪癖已够用   |

### B 记忆 —— 它记得什么

| 需求               | 阶段  | 必要性     | 状态   | 说明                                                                                 |
| ---------------- | --- | ------- | ---- | ---------------------------------------------------------------------------------- |
| 记忆系统 v1/v2       | S2  | 核心      | ✅    | 六类别 + 五维标签；**追加式时间线**（同主题新进展新记一条、不去重）；双时间维度（事发/存储）；/memfill 历史回填                  |
| A/B 两级库（B 库长文本）   | S2  | 核心      | ✅    | 长文本存 B 库配摘要，召回只给摘要，追问细节才展开全文省 token                                               |
| 每日回顾             | S2  | 增强      | ✅    | 睡前复盘：补记遗漏、修正错误记忆                                                                   |
| 信息调度层            | S2  | 核心      | ✅    | context.py 统一组装：**便签 > profile > 记忆 > 上下文**；记忆渲染成临时 system 注入（随每轮 query 变化）         |
| 记忆检索工具（AI 自主回想）   | S2  | 核心      | ✅    | function calling：TA 自己决定何时查、查什么，最多 3 轮；召回为空返回"（记不清了）"                              |
| **语义化召回（向量检索）**   | S4  | **核心**  | 待做   | 现为纯字面 bigram，"几点睡"召不回"熬夜"。本地 bge-small-zh-v1.5。**你指认的"目前最大问题"，建议列 S4 首位**          |
| 今日对话回顾线          | S2  | 增强      | ✅    | 当日对话留原始素材供复盘/日记；PURGE_REVIEWED_MESSAGES 可配复盘后清除                                     |
| **事件记忆与关怀触发**    | S4  | 核心      | 待做   | 事件 schema `{event,time,type,followup}` + 事前/事后/心情跟进 + **优雅失败（最多 1 次轻触、不纠缠）**。⚠️ 按宗旨记的是 **TA 记下的、和对方有关的事**，不是"用户事件" |

### C 主动 ★ —— 它主动找你（产品核心）

| 需求         | 阶段  | 必要性  | 状态    | 说明                                                                       |
| ---------- | --- | ---- | ----- | ------------------------------------------------------------------------ |
| 主动触发引擎     | S1  | 核心   | ✅     | 问候 + 话题（时间临近 / 信息命中 / 闲聊发起）+ 简版作息                                         |
| 阶段化频率策略    | S1  | 核心   | ✅     | 初见期空闲 30–60min 冒泡（独立额度 12/天）；熟悉期主动只由触发源发起                                |
| 防打扰 guard  | S1  | 核心   | ✅     | 每日上限 6、忙碌静默期、连续未回复停发、睡觉拦截、游戏中暂停                                          |
| 对话中的主动延续   | S3  | 核心   | 待做    | 对话内也会追问/延伸/转移话题，而非一问一答即止（部分靠人设 prompt，成本低）                               |

## 四、必要性判定：砍掉与降级

以下条目本轮**不进排期**，附理由（都是判断，可推翻）：

| 条目                   | 判定           | 理由                                                                                         |
| -------------------- | ------------ | ------------------------------------------------------------------------------------------ |
| **财富系统**（原 P2 独立条目）  | **降级：并入工作系统** | 钱是纯叙事资源，而它**目前唯一用途就是"打断有代价"**——与打断成本高度重复。先不独立，Money 作为工作系统内部变量；等有真实消费出口（如它用钱给你买点什么）再说     |
| **时间计划系统**（原 P3）      | **砍掉**       | AI 日程 + 用户日程 + 日历 + 时间表太重，自用用不上；"记住你的事"已由 B 模块事件记忆承担                                       |
| **伴侣/助手分身**（原 P3）     | **砍掉**       | 分身 = 围着用户转的不同角色，与「一视同仁」宗旨**直接冲突**                                                          |
| **阅读修炼人格**（原 P3）      | **砍掉**       | 人格随阅读漂移会破坏"朋友是稳定的锚"——朋友的性格不该乱变；且效果极难验证                                                    |
| **群聊·时间统一 get_time**  | **砍掉**       | 群聊已移除（v0.27）；私聊里各朋友各自生活日是**个性化视角**，不是 bug                                                  |
| **未成年人保护**            | **N/A**      | 自用单用户，不适用。若将来开放给他人再启用                                                                      |
| 名字多面共存                | **降级为可选**    | 正确性洁癖级：当前单值能跑，只是与宗旨不完全一致。重构名字层成本高，等真遇到多名字场景再做                                              |
| 人格体系 v2               | **降级为可选**    | 6 骨架 + 怪癖已够用；先调研有没有更好做法                                                                    |
| 对话双线（审查线）             | **降级为可选**    | 双倍 token 换"不突兀"，收益不确定。**建议先实测**：如果回复质量本来就没问题，就不做                                           |
| 防沉迷时长提示               | **降级为可选**    | 挂 HUD，但自用单用户下优先级最低                                                                         |
| 鸿蒙端载体                 | **移出需求池**    | 这是**载体决策**不是功能需求，回到待确认清单 #7                                                                |
