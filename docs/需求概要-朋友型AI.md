# 朋友型 AI · 需求概要 v0.81





































> 一个**自己专属**的朋友型 AI，核心特征是**主动**——它不等指令，而是有自己的作息、工作、记忆和生活节奏。
> **一句话价值主张**：让 AI 从"随叫随到的工具"变成"有自己生活的伙伴"。
> 📦 历史部分已拆出：**v0.2–v0.26 版本记录 + 实测反馈 #1–#15 全文 → [历史归档-版本与实测.md](./历史归档-版本与实测.md)**
> 📦 **v0.27–v0.76 版本更新记录已拆出独立文档 → [版本更新记录.md](./版本更新记录.md)**




> **进度**：S1 能聊 ✅ 收官（10-05）；S2 像人 ✅ 收官（10-08）。**S3 有自己的生活 = 当前主线**（与网页端 Web UI 并行）。S4 待启动；S5 自用阶段暂缓。

## 一、产品定位与项目约定

| 维度 | 结论 |
| --- | --- |
| 目标用户 | 自己专属（单用户，深度个性化） |
| 载体形态 | **两阶段已定档**：自用阶段 **网页端 Web UI**（浏览器打开就聊，服务端常驻本机）；推广阶段 **鸿蒙 App**（服务端上云）。成本暂不考虑 |
| 模型/运行 | 云端 API（DeepSeek）；自用阶段服务端跑**本机**，推广阶段迁**云服务器** |
| **一视同仁** | **项目宗旨**：AI friend 是独立个体，不知道"用户/主人"这种特殊身份，平等对待所有其他人（包括你）。记忆、日记、称呼都不围绕你特殊化——TA 记的是对自己有趣/重要/相关的事，日记是 TA 自己的生活 |
| 工具观 | 工具不是外部 API，是 TA 自己的"身体组分"（记忆检索=大脑回忆、行为接口=作息意愿）。**两层分离**：拟人化只管体感外壳，function calling 的契约内核（何时调/调哪个/参数/返回结构/标记 token）必须清晰 |
| 用户称呼 | 称呼来自每个朋友自己的 profile（事实便签"叫我X" > profile 称呼 > config.USER_NAME 兜底），不同朋友可有个性称呼，代码不写死 |

## 二、模块地图

### 2.1 模块划分

需求池不再按优先级排长龙，改按**能力域**分成 8 个模块（A–H）。模块是稳定的，阶段是推进节奏。

| 模块 | 一句话 | 覆盖阶段 |
| --- | --- | --- |
| **A 人格与身份** | 它是谁 | S2 → S4 |
| **B 记忆** | 它记得什么 | S2 → S4 |
| **C 主动** ★ | 它主动找你（产品核心） | S1 → S4 |
| **D 生活** | 它自己的日子（作息/工作/被打断） | S1 → S3 |
| **E 对话与互动** | 它怎么说话、和你一起玩什么 | S2 → S3 |
| **F 自主** | 它自己掌控自己 | S2 → S4 |
| **G 载体与工程** | 跑在哪、怎么运维 | S1 → S3 |
| **H 合规与安全** | 底线（自用阶段⏸暂缓，推广前必做） | S3 → S5 |

### 2.2 阶段推进节奏

原 P0–P3 已混乱（P2 里混着已完成项、P3 里混着重要项），重排为 S1–S5：

| 阶段 | 主题 | 主线模块 | 状态 |
| --- | --- | --- | --- |
| **S1 能聊** | 先跑起来 | C + D + G | ✅ 已收官 |
| **S2 像人** | 说话像、记得住 | A + B + E | ✅ 已收官 |
| **S3 有自己的生活** | 它有边界、有日子过 | D + E + G | 🔵 **当前主线** |
| **S4 越来越懂你** | 召回准、会关心 | B + C + F | ⚪ 待启动 |
| **S5 底线与边界** | 合规护栏 | H | ⏸ 自用阶段暂缓 |

**必要性分级**：核心（没有它产品不成立）/ 增强（显著提升"像人"的程度）/ 可选（锦上添花）/ 不做（本轮砍掉，理由见第四节）。

## 三、需求池（按模块）

### A 人格与身份 —— 它是谁

| 需求 | 阶段 | 必要性 | 状态 | 说明 |
| --- | --- | --- | --- | --- |
| 人格池系统 | S2 | 核心 | ✅ | **15 骨架**（v0.79）× 随机名 × 随机怪癖，/new-friend 开盲盒且不可重摇——"没得选才是朋友" |
| 初识系统 | S2 | 核心 | ✅ | 关系阶段 new/familiar；初见期不查户口、按氛围追问；信息清单按朋友隔离（新朋友零了解开局） |
| profile 自动维护 | S2 | 核心 | ✅ | 提取器把确定性事实（称呼/生日/城市等）写进清单；用户手填的字段不覆盖；**留痕**：每条自动字段存 B 库上下文证据、A 库挂链接、`/profile why` 可查；**稳定字段冲突不静默覆盖**、标 pending 待用户确认 |
| profile 定期审查 | S4 | 增强 | 待做 | 每日回顾时审一遍字段，发现错误/新信息就修正。属「自我审查」大类 |
| 人格体系 v2 | — | 可选 | 待做 | 百分比性格调料 / MBTI 等细致化。**先调研**有没有更好的做法；除非实测发现人格不够鲜明，否则 6 骨架 + 怪癖已够用 |
| **结构化人格内核（V3）** | S4 | **核心** | ✅ | 人格从"形容词"升级为**具体到能被违反的判断**：每张卡一份 `kernel`（一句话内核 + **它不是什么** + 带强度的好恶 + 立场卡 + 雷区 + 生活事实卡 + 语言指纹 + 反谄媚参数 + 状态初值），**v0.79 骨架扩充到 15 张**（原 7 张抽出来容易撞脸，新增：学者型/生活家/猫系/江湖气/文艺青年/实干派/闷骚损友/直球）；**三档渲染**（full 给独白层 / compact 给 system / voice 给说话层）；旧卡按 archetype 自动补，老朋友也有判断清单。⚠️ 事实卡里不写职业和正在做的事（那是工作系统的地盘） |
| **反谄媚硬约束** | S4 | **核心** | ✅ | 五条硬规矩，优先级高于"像个好朋友"：**镜像预算**（不许跟着说"我也是"，不许借对方的校园/考试给自己捏人设）、**异议配额**（立场冲突时 40–65% 要表达不认同）、**禁无条件投降**（给替代反应清单：嘴硬/部分承认/反问/岔开）、**话题主权**（每 N 轮起自己的话题、允许说完就停）、**回复自主权**（有权只回"嗯"、有权不热情）；元规则：不许讲关系进度 |
| **双层生成（内心独白 → 说出的话）** | S4 | 核心 | ✅ | 每轮先跑一次**不可见的内心独白**（9 段结构化自问，含"和旧立场冲突吗"），立场在第 1 层定住；第 2 层只做翻译、"怎么说"随便、"说什么"不许改。**独白失败退化单层**。代价：每轮多一次 LLM（限 `max_tokens`） |
| **语气主轨（割裂治理）** | S4 | 增强 | ✅ | 每轮由 mood + 上下文定**一个**主导情绪状态，其它注入（打断成本 / 反谄媚 / 今日素材 / selfmem）全部从属；「话题主权（分享）」和「异议（怼）」排队，别在同一句里既嘴硬又硬分享。**已落地**（v0.56）：新增 `tone.py` 把 mood（主轨）+ cost（从属相处姿势）收成一条【此刻的我】块；反谄媚补「分享/异议排队」协调条款；治"上一秒怼、下一秒分享"（实测 #36 #6） |
| **修炼人格（偏好养成）** | S4 | 增强 | ✅ | 偏好不再写死、从真实经历里**养成**（2026-10-11 用户拍板，是原「阅读修炼人格」的升级复活）。**三层**：内核（好恶强度/立场/雷区/语言指纹）**钉死不漂移**（防重蹈"朋友是稳定的锚"覆辙）；物理生活偏好（听歌/小店/房间等）降为**被动底色**（被问才答、不当主动话题）；兴趣偏好从**读/聊/刷**三源动态**强化/养成**。**机制**（用户拍板）：主动消息话题源=三源；意识流里 TA 表达了"感兴趣"的想法 → **即时规则记兴趣线索**（不调 LLM）；同一兴趣对象在流里出现 N 次 → **自动转正**成新偏好（不调 LLM）。**已落地**（v0.67）：新增 `interests.py`——阅读源 `work._settle` 读 genre 直接 +1、聊天源独白/回复「信号词+主题词」共现记线索（`corpus.INTEREST_SIGNALS/INTEREST_TOPICS`）、同一主题累计 ≥3 自动转正；转正偏好进 `kernel_prompt`「最近喜欢上的」块 + `context._inject_random_topic` 主动话题弹药；刷手机源占位。开关 `INTEREST_PROMOTE_ENABLED` |

### B 记忆 —— 它记得什么

| 需求 | 阶段 | 必要性 | 状态 | 说明 |
| --- | --- | --- | --- | --- |
| 记忆系统 v1/v2 | S2 | 核心 | ✅ | 六类别 + 五维标签；**追加式时间线**（同主题新进展新记一条、不去重）；双时间维度（事发/存储）；/memfill 历史回填 |
| A/B 两级库（B 库长文本） | S2 | 核心 | ✅ | 长文本存 B 库配摘要，召回只给摘要，追问细节才展开全文省 token；**profile 清单证据也走 A/B 库**——A 库记忆挂 long_id → B 库对话原文 |
| 每日回顾 | S2 | 增强 | ✅ | 睡前复盘：补记遗漏、修正错误记忆 |
| 信息调度层 | S2 | 核心 | ✅ | context.py 统一组装：**便签 > profile > 记忆 > 上下文**；记忆渲染成临时 system 注入（随每轮 query 变化） |
| 记忆检索工具（AI 自主回想） | S2 | 核心 | ✅ | function calling：TA 自己决定何时查、查什么，最多 3 轮；召回为空返回"（回忆不起来了）"（拟人化文案按 AGENTS.md 约定，就近在 memory.py 维护） |
| **语义化召回（向量检索）** | S4 | **核心** | ✅ | 本地 bge-small-zh-v1.5（onnxruntime，不需要 torch/GPU），与字面 bigram 混合打分——「几点睡」能召回「熬夜」；模型/依赖不可用自动退回纯字面。向量存 `memory_vectors` 表、惰性补算持久化。**你指认的"目前最大问题"，已治本** |
| **今日上下文（今天做过/读到的事）** | S4 | 核心 | ✅ | 工作产出的素材顺手落 B 库（`今日素材` 标记，不额外调 LLM），当天每轮注入「你今天做过的事」；**跨天自动不再注入**（=写日记后从上下文清除），B 库记录保留。治"问它今天干了啥答不上来" |
| **艾宾浩斯记忆衰减** | S4 | 核心 | ✅ | 遗忘=一次次总结：到期压短一级（L1≈50字/L2≈20字），压到 `MAX_LEVEL` 删行（连带 B 库长文+向量）；被想起越多有效期越长，够多次→永久。`decay_level`/`pinned` 两列带旧库迁移。挂睡前复盘一天一次，`/decay` 手动。保真优先：压得不好就跳过不改 |
| **自我记忆（我说过的话）** | S4 | **核心** | ✅ | `selfmem.py`：记"我自己的事"——立场 / 我答应过的事 / 我出过的糗 / 想聊没聊成的 / 对这个人的感觉 / 上次的内部状态；睡前一天一次 LLM 复盘写入（`diary.daily_review` 末尾）。**不参与艾宾浩斯遗忘**（"我说过的话"淡忘了 = 人格断裂）；每轮召回几条做**一致性检查**（这次别跟上次反着说）；内部状态跨天延续并每天向人格中位值拉回 20% 防漂移。命令 `/selfmem`、`/selfreview` |
| **人格红线体检** | S4 | 增强 | ✅ | `corpus` 三组正则（投降句式 / 关系进度跑分 / 对方在反驳我）+ `persona.redline_report()`：core 每轮检查，**只告警不改写**（替换成模板句会把一个人改成安全台词）。命中=反谄媚 prompt 没拦住，按这条证据回去调 prompt |
| 今日对话回顾线 | S2 | 增强 | ✅ | 当日对话留原始素材供复盘/日记；PURGE_REVIEWED_MESSAGES 可配复盘后清除 |
| **事件记忆与关怀触发** | S4 | 核心 | ✅ 承诺提醒 | 承诺/约定已落地（`events.py`：记住"我答应对方要做的事"→ 到点提醒，醒着发、睡着醒来补、过期错过、优雅失败不纠缠）；**事前/事后/心情跟进**（考试/面试/生日等事件的关怀）仍待做。⚠️ 按宗旨记的是 **TA 记下的、和对方有关的事**，不是"用户事件" |

### D 生活 —— 它自己的日子

| 需求 | 阶段 | 必要性 | 状态 | 说明 |
| --- | --- | --- | --- | --- |
| 时间感知 | S1 | 核心 | ✅ | system prompt 注入日期/时间/时段 |
| 休眠（简版） | S1 | 核心 | ✅ | 夜间休眠 + 迷糊回复；WAKE/SLEEP_HOUR 可配 |
| **打断成本机制** | S3 | **核心（招牌）** | ✅ | `cost.py`：`costIndex = R×(1+F)` → welcomed/tolerated/costly；**R** 由 phase/flow 给（心流 1.0 > 忙 0.7 > 闲 0.3 > 收工 0），**F** 由精力推的疲劳（越低越累代价越高）；三态落到**回复语态**（`context` 注入"此刻的相处"）；**红线兜底改写**（命中 `COST_BLAME` 换 `COST_SAFE_LINES` 安全句）。安全阀=紧急通道（窗口内跳过打断成本）。⚠️ 参考文档原公式是 R=剩余压力(Q-P)/Q、F=打断频率，已简化，见下方"公式升级"待做条目 |
| 打断成本公式升级（参考语义） | S4 | 增强 | 待做·后续升级 | 参考文档原公式：R=(Q-P)/Q 剩余压力（越接近读完越能承受打断）、F=Σ 打断次数×时间衰减 + **B 疲惫值**（打断累积，costly 后下次"累"）。现用 R=心流阻力 / F=精力疲劳（10-09 简化），作后续升级 |
| V 消息优先级 | S4 | 增强 | 待做·后续升级 | 参考文档：情感支持/情绪低落判定为高优先级 → 直接 welcomed、代价由系统吸收（关系+）。现仅紧急通道（急事），情感维度判定后续升级 |
| **HUD 三态徽章** | S3 | 核心（招牌） | ✅ | 顶部 phase 旁加打断成本三态徽章（有空/还行/正忙，绿/黄/红）——看得见"现在找它合不合适"，才会自发尊重它的边界 |

### 7.4 Gitee 双仓库方案（10-10 已落地 ✅）

- **动机**：服务器（腾讯云，150.158.147.51）直连 GitHub 极不稳定（实测连续超时 134s），拉不动代码
- **方案**：同时维护 GitHub + Gitee 两个 remote；**服务器从 Gitee pull**（实测 0.5 秒），GitHub 作为对外展示/备份
- **落地结果**：
  - Gitee 仓库：`https://gitee.com/Charlie929-dot/friend-ai`（**私有**，与 GitHub 对齐）
  - 本机 remote：`origin`=GitHub，`gitee`=Gitee
  - 服务器 `/opt/friend-ai` 的 remote `gitee` 已配好（含 token），`main` upstream 指向 `gitee/main`
  - **实测数据**：GitHub pull 超时 134s ❌ ↔ Gitee pull **511ms** ✅
- **日常同步**：本机 Git Bash 执行 `bash sync-to-server.sh`
  - 自动双推 GitHub + Gitee → 服务器从 Gitee 拉 → 装依赖 → 重启 → 自检
  - Gitee 拉失败时自动退回 git bundle 走 SSH 直传（彻底不依赖外网）
  - 令牌从环境变量 `GH_TOKEN` / `GITEE_TOKEN` 读，**不写进脚本**（已加到 `~/.bash_profile`）
- **注意**：Gitee 免费版单仓库限 500MB，本仓库很小（几百 KB）无压力
