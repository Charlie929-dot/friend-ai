## 一、产品定位

一个**自己专属**的朋友型 AI，核心特征是**主动**——它不等指令，而是有自己的作息、工作、记忆和生活节奏，像朋友一样在合适的时刻主动出现。

**一句话价值主张**：让 AI 从"随叫随到的工具"变成"有自己生活的伙伴"。

**关键决策（已确认）**

| 维度     | 结论                                      |
| ------ | --------------------------------------- |
| 目标用户   | 自己专属（单用户，深度个性化）                         |
| 载体形态   | 接入现有 IM（机器人形态）                          |
| MVP 范围 | 主动触发引擎                                  |
| 工具观    | 工具不是外部 API，是 AI 自己的"身体组分"——记忆检索=大脑回忆、行为接口=作息意愿；描述用"我可以回想"、返回用"想起来了/回忆不起来了"，不出现"搜索/工具/数据库"类词（2026-10-08 定）。**两层分离守则（2026-10-08 补）**：拟人化只管"体感外壳"（我是谁/我在干什么），function calling 的"契约内核"——何时调、调哪个工具、参数枚举（source=group/private）、工具间依赖（见长文标记才 recall_detail）、返回结构——必须保留清晰；机器可读的标记 token（如长文标记）不得随拟人化改词，否则 AI 会找不到触发条件导致调用失败 |
| 用户称呼   | 称呼来自 profile、不写死——每个朋友有自己 profile 里的"称呼"字段（事实便签"叫我X" > profile 称呼 > config.USER_NAME 兜底），**不同朋友可有个性称呼**；AI 提取时把基本信息（含称呼）记进 profile、定期审查（2026-10-08 定） |
| 当前阶段   | ~~想法阶段，无代码~~ → P0 已收官（2026-10-05），进入 P1 |

## 二、MVP：主动触发引擎

让"主动"先跑起来，其余系统全部后置。MVP 包含三个子系统：

### 2.1 主动问候

- 早 / 中 / 晚定时主动问好
- 问候语需结合上下文（天气、近期聊过的事），避免机械复读

### 2.2 主动话题

三类触发源，按优先级排列：

| 触发源  | 说明                                   | 数据源                           |
| ---- | ------------------------------------ | ----------------------------- |
| 时间临近 | 用户提到过的计划时间、特殊节日                      | 简易日程记录（先不建完整时间计划系统，聊天记录里提取即可） |
| 信息命中 | 搜集到的信息与用户画像重叠 / 提及过的人事物 / 趣味猎奇治愈内容达标 | 轻量信息搜集（RSS/订阅源起步，不做全网搜索）      |
| 闲聊发起 | 低频率随机开启话题，维持存在感                      | 对话模型自身                        |

**防打扰约束（MVP 必须有的刹车）**

- 每日主动消息上限（如 ≤6 条）
- 用户明确表现出忙碌/不耐烦后，进入静默期
- 静默时段（如凌晨 0-7 点）不主动发消息

### 2.3 休眠作息（简版）

- 默认规律作息：夜间进入休眠，早上"醒来"时主动问好（与 2.1 联动）
- 休眠期间用户发消息，随机回复"睡觉信号"类迷糊回复
- **暂缓**：随机 5-30min 离线工作、唤醒按钮、扣财富（依赖财富系统，P2）

### 实测反馈记录 #8（2026-10-07，失忆自证循环）

**Bug：初遇朋友私聊"依然不记得群聊的事"——越问越失忆**

- 现象：修复 #7 后实测，用户问初遇朋友"你现在想起来群聊的事了嘛"，仍答"真没有"，且各朋友（小葵/阿燃）也跟着说"初遇失忆了"
- 根因（关键，不是召回问题）：**记忆被"失忆"这件事污染**。之前初遇朋友确实不记得（旧 bug），用户反复追问"记不记得"，提取器把对话过程当记忆记了下来——`小徐发现我不记得群聊内容，说我失忆了`、`小徐不愿相信我不记得、反复追问`、`初遇失忆了，连群聊的事和阿燃都不记得`……这些错误记忆字面含"群聊/失忆"，bigram 得分反而最高，私聊时排在真实群聊记忆前面，AI 一读就"我确实不记得" → 形成自证循环
- 修复（2026-10-07）：①**提取器防污染**——`_validate` 加 `_SELF_AMNESIA`（我不记得/我失忆/我想不起来/我忘了）与 `_MEMORY_QUIZ`（追问/是否还记得/记不记得）两道确定性正则丢弃，EXTRACT_PROMPT 质量红线加"不记失忆类"（含"某位朋友失忆了"这种别人视角描述）；②**清理数据**——备份后删掉全库 18 条污染记忆（初遇朋友 5、阿燃 7、小葵 1，含归档副本）。清理后实测召回即恢复正常（返回真实群聊记忆）
- 经验：记忆系统的正确性 = 提取层（记对）> 召回层（找得准）。召回算法再准，库里存了"我不记得"也会被召回到前面；向量检索解决不了"记错"的问题

### 实测反馈记录 #9（2026-10-07，"记得小葵吗"还是接不上）

**Bug：问"记得小葵吗"，只召回"小葵拿快递/赌奶茶"的琐事，召不回"介绍认识"的身份记忆**

### 实测反馈记录 #13（2026-10-08，记忆调度缺"深度思考"）

**问题（用户指认"目前最大问题"）：群聊里问过的事，私聊里"翻了一遍"说没有**

- 现场：用户对小葵说"早上的群聊，不记得了吗"（暗示群里说过几点睡）；小葵调检索"翻了一遍"答"群里你就没说过具体几点"，还翻旧账"上次问你也是先别在意糊弄过去"
- 四层根因：
  1. **召回纯字面 bigram**：recall 打分是 bigram/单字重叠，"几点睡"与"熬夜/凌晨才睡/作息不规律"字面不重叠 → 得分 <1.0 门槛 → 召不回；反而"上次问几点睡"这种元信息记忆字面命中、排到前面
  2. **群聊记忆私聊召不回**：recall(group_first=False) 时群聊记忆只有最近 5 条加温和分（GROUP_RECENT_BONUS=1.2），更早的靠字面关键词；"早上的群聊"那条不在最近 5 条 + 字面不匹配 → 必丢
  3. **AI 不懂"群聊"要专门搜群聊来源**：search_memories 工具描述没提群聊，底层 group_first=False，AI 搜的时候不会优先群聊记忆
  4. **检索空集被当绝对事实**：小葵把"没搜到"等同于"你没说过"，而真人会说"我印象里好像没说，也可能记漏了"
- 方案落地进度（2026-10-08）：✅ ①search_memories / recall_detail 加 source 参数 + recall 按来源过滤 + 工具描述补"提到群聊优先搜群聊"（快速止血已做）；✅ ③检索前意图重写（query 参数描述引导重写成关键词）；✅ ④召回为空返回"（记不清了）"大脑反馈（用户改进：工具返回直接做成"记不清"，比 prompt 里加规则更贴 function calling 机制、更贴真人"想不起来"的体感）；⏳ ②语义检索（向量）仍是治本底座、待做
- 本质：文档早就规划的"向量检索"到了该落地的时候——字面匹配是"没深度"的根源，语义检索 + 检索工具更聪明（来源感知 / 意图重写）是治本组合。落地顺序建议：先 ②③④（prompt + 一个参数，立刻缓解"群聊记忆私聊召不回"），再 ①（向量检索，治本底座）

### 实测反馈记录 #14（2026-10-08，工具观踩线 + 自我审查归并）

**问题①：工具观会不会导致工具调用失败？**

- 结论：工具观本身不会，但拟人化不能越过"契约信息不丢"的底线。function calling 要成功，模型必须从 schema 读到四样硬信息——①何时调 ②调哪个（search_memories 快速回想给摘要 / recall_detail 展开细节）③参数怎么传（query 关键词、source 枚举）④返回结构 + 工具间依赖（看到长文标记才调 recall_detail）
- **已踩线的一处**：`_TOOL_LONG_MARK` 拟人化成"【还记得更细，可以再回想一下】"，但 `_TOOL_DETAIL_DESC` 仍写"结果里标了【有长文】才用它展开"——前后对不上，AI 调 search_memories 拿到结果找不到"【有长文】"标记，可能不触发 recall_detail。根因：把机器可读的**标记 token** 也一起拟人化改词了
- **守则（两层分离）**：拟人化只管"体感外壳"（我是谁/我在干什么），"契约内核"（触发时机/工具分工/参数枚举/返回结构）必须保留清晰；机器可读标记 token 不得随拟人化改词。已写入关键决策表"工具观"行 + 「AI 自主行为接口（MCP）」条目。✅ 已修（2026-10-08 方案1）：长文标记保留"长文"契约词——`_TOOL_LONG_MARK`="【还有长文，可以再回想一下】"、`_TOOL_DETAIL_DESC` 引用同步"标了【还有长文】"，前后一致

**问题②：定期审查与双线是否重叠？**

- 结论：不重叠，但都叫"审查"易混。三者同属「自我审查」（AI 检查自己有没有出错）大类，对象/频率/时机不同：
  - **对话线·审查线**：实时、逐句审"回复内容"（阅读/编写缓冲期），待做
  - **定期审查 profile**：周期性、批量审"profile 字段"（挂每日回顾），待做
  - **记忆修正**：每日回顾审"记忆库"，已做
- 归并处理：三条需求各自补一句交叉标注，说明同属「自我审查」、不重复，避免后续立项时误判为同一件事
