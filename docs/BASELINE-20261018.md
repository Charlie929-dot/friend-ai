## 3. 当前基线测试结果（2026-10-18 实测）

- **结果：全量 92/92 通过，exit 0，耗时约 35 秒**。
- ⚠️ **执行环境坑（重要）**：在 DSH 会话的默认沙箱（workspace-write）里跑会出现大批 `sqlite3.OperationalError: unable to open database file`（临时库建不起来），大量用例假失败——这是已知的「沙箱 + CPython 0o700 ACL」组合问题（handover 会话 b6862a63 已坐实先例），**不是代码问题**。正解：对 pwsh 调用传 `sandbox_permissions="danger-full-access"`（等价普通用户终端）再跑，92/92 正常。普通终端（PowerShell/cmd 直接开）跑不受影响。

## 4. 实现前必须知道的约束（3~6 条，从 AGENTS.md / 文件改动同步清单提炼）

1. **锁与切库互斥**：所有依赖「当前朋友库」一致性的多步流程与切库互斥——`db.PATH_LOCK`=全流程（回复/提取/切库）、`db.SEND_LOCK`=收发入口与切库（RLock，命令内部与 /api/send 外层都会拿，锁序：切库命令 = PATH_LOCK 内再套 SEND_LOCK，**别反**）。每朋友一份 `friend-<id>.db`，加表必须考虑旧库迁移。
2. **锁内不能再嵌套调 LLM 的完整人设**：内部 LLM 调用（记忆提取/素材生成/结算）一律用 `persona.core_identity_prompt()`，拼 `build_system_prompt()` 会成环递归爆栈（实测 #17）。
3. **`life.py` 的派生契约不能落库造假**：进度/精力/phase 全是派生投影不落库；手工造 `day_state` 夹具必须带 `v:2`+`planned:1`；phase 键集合（idle/working/flow/break/off/sleep）是跨十个消费模块的契约，**别改键名**；测试里「精力/进度」不能靠写字段造假。
4. **测试纪律（约定 #10/#11）**：每个测试文件顶部必须 `from _test_common import *`（三段全局机制：`.test-tmp/` 收口 + `INNER_MONOLOGUE_ENABLED=off` + `WORK_SHAREABLE_ENABLED=off`）；DB 重定向/config 改值一律用 `_patch_config`，收发用例套 `**_FAST_TIMING`，排班断言预置 `rest_schedule`——**别再手写 save/set/restore**。
5. **改默认值双头维护**：行为参数默认值在 `config.py`，`tuning.py` 面板元数据清单同步登记（`default` 一律 `getattr(config, k)` 推出、不手写），`.env.example` 同步；改了文件先查 `docs/文件改动同步清单.md` 对应行把「必须同步」项做掉。
6. **改完必做五步顺序**：改全部代码（含 web 调试面板入口 + `webui.py` 接口）→ `run_tests.py` 全量转绿（含 `EXPECTED_TOTAL` 同步）→ 改文档（需求概要版本记录 / 实测反馈 / AGENTS / handover_write）→ `git add -A && git commit`（中文 message）→ `bash sync-to-server.sh`（本 worker2 阶段**不 commit / 不 push**，等拍板人确认）。
