## 2. 任务模型重构（核心）

### 2.1 新模型

- **当日任务** = 圈定的整数章节总字数 `total_chars`（`trueread.plan_day` 已有，保留）。
- **进度** = 已读字数 ÷ `total_chars`（连续百分比，不再"完成 N 件"）。
- **经验** = 进度百分比（0–100，满=100），替代"钱/余额"。经验 ∝ 工作量（已读字数）。
- **起晚**：实际起床晚于 `SCHED_WORK_START` → 触发"起晚"事件（意识流记一笔，让 TA 知道自己起晚了），之后照常读、速度不变、不追进度 → 自然读不满 100% → 经验打折。
- **加班**：过 `SCHED_WORK_END` 仍进度 <100% → 继续读到读完，按字数判定（不是按半节数）。
- **8 半节**：`half_periods()` 真正接入，作为"累了歇一下"的休息节奏；进度不绑半节。

### 2.2 落地要点

- 已读字数 = **已投入阅读分钟 × tps**（tps = `total_chars` ÷ 320min 推导，不单调）。起晚 → 投入分钟少 → 读得少，天然不追进度。**（此点为我建议，动工时最终确认）**
- 读书笔记（章节结算）照旧"读完一章产一条"，触发点改为"已读字数跨过该章边界"。
- 废弃 `WORK_UNIT_MINUTES` / `WORK_BREAK_MINUTES` / `WORK_DAILY_QUOTA` / `WORK_PAY_PER_UNIT`。
- 精力（energy）保留，改"每半节消耗、节间休恢复"。
- `tuning.py` 面板"工作系统"组删重复时间项，只留一套任务排班 + 经验/精力等叙事参数。
- money → experience 全局替换：`work.py` / `stream.py`（"攒了多少 X 块"→"进度 X%"）/ `webui.py`（HUD）/ `web/index.html`（"余额"→"经验"）/ `commands.py`（`/work`）/ `tuning.py` / `config.py` 注释。

## 3. 其余改动

- **主动消息收敛**：`context._inject_random_topic` + persona 主动 prompt 去掉自由发挥聊环境；random 无真实弹药即跳过。
- **细线调亮**：`web/index.html` 的 `.outline-rail i`（重点 `.l1` 跨天）用强调色调亮；`.ol-day` 不动。
- **连发间隔**：`core.py` 分段连发 `segments[i-1]` → `segments[i]`（取决于下一句字数）；数值 0.08 / 0.6 / 5 暂不动。
- **两个 bug**：①`library._parse_epub` 过滤前言/版权/说明页（title page、copyright、Standard Ebooks 说明页、目录页等），不进 `chapters`；②真读推进时同步 `library.progress()`，治"读到第 801 段"卡住。
- **排查 10 点醒**：服务端常开却 10 点才醒，查服务器时区 / 代码未同步 / 赖床卡住。
