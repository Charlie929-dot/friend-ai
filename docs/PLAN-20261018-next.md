### 候选 A：断线重连与连接状态体验（web 前端）⭐ 推荐

**现状证据**：
- `web/index.html:1490` 与 `:1508`：`poll()` / `initialLoad()` 的 catch 只写一行 `statusText.textContent='连接断了，重连中…'`，**没有任何退避/重试/恢复逻辑**；
- `web/index.html:2566`：`setInterval(poll,900)` 固定 900ms 盲轮询——服务端不可达时每 0.9 秒打一次失败请求，永不停歇；
- `web/index.html:643`：`@media (max-width:520px)` 下 `.fh-status { display:none }`——**手机上连「连接断了」这行提示都没有**，用户只能对着一个死页面干等；
- `web/index.html:2460`：`sendText()` 失败只 `addSys('⚠ 发送失败：'+e.message)` 一条灰字，**没有重试按钮、消息文本不回填**，断网时打的长消息直接丢失（要重打）；
- 需求池 G 模块「断线重连提示」条目（`docs/需求概要-朋友型AI.md:199`）：状态「待做」，原文「现在断线只报一行『连接断了』，要能自动重连并给提示，而不是干等」——**用户已明确定义的待办**。

**为什么值得做**：
1. 这是需求池里**用户亲自登记的待办**，不是我们推演出来的需求；
2. 自用阶段主载体是网页端（手机+电脑双端），服务器重启/网络抖动是日常事件（`sync-to-server.sh` 每次同步都会重启服务）——每次同步后手机端体验就是「死页面」；
3. v0.107–v0.109 刚做完移动端适配三部曲，连接体验是移动端收尾的自然下一块；
4. 纯前端改动（`web/index.html` 一个文件），**不动 .py、不动数据结构、不动接口**，影响面是全项目里最小的。

**影响面**：`web/index.html` 单文件；无后端改动；测试上「网页端 Web UI」用例加页面结构断言（项目惯例，见 v0.101/v0.109 做法）。

**风险**：低。最坏情况是前端提示文案错误，刷新即恢复。回滚 = revert 单文件。

**外部依据**（web_search 查得；本会话 web_fetch 被网络沙箱拦截无法抓全文，以下以搜索摘要为准，标注 ⚠️）：

**实施要点（分步清单见 §2）**：前端网络状态机（online/offline）+ 轮询退避（连续失败 → 逐级拉长间隔，如 0.9s→2s→5s→15s 封顶，恢复后立即回到 0.9s）+ 恢复提示（「连接回来了」横幅 + 补拉消息）+ 发送失败重试（失败消息回填输入框或提供重试按钮）+ 移动端可见性（≤520 不再隐藏连接状态，至少用 toast/横幅形态）。

### 候选 C：阅读老啃古腾堡前言（txt 剥离头尾）

**现状证据**：
- `docs/体验优化清单.md:55` 候选池登记：「《Oliver Twist》800 段往后还在读版权说明/协议页，一啃好几天——`library` 的章节切分对 Project Gutenberg 文本没剥头尾（epub 有 `EPUB_FRONT_JUNK` 过滤、txt 没有）。候选：txt 也剥 `*** START`/`*** END` 之间的正文」；
- 代码核实：`library.py:270-282` `_parse_txt` 直接全文进 `_split_passages`，无任何头尾剥离；`_is_front_junk`（`library.py:289-300`）只对 **epub** 的章节列表生效（`_parse_epub` :380 调用），txt 的章节由 `_txt_chapters`（:206）切分、**不走 `_is_front_junk`**；
- 加重因素：`_txt_chapters` 的正则 `_CHAPTER_RE`（:202-203）只认「第X章/回/节/卷/部/篇」——**英文书根本切不出章节**，整本走 fallback 按字数切，Gutenberg 头部（标题页+许可证+制作信息，通常 300-600 行）会被并进第一章（:228-231 的「章前内容并进第一章」逻辑），TA 要多啃好几天。

**为什么值得做**：这是**正在流血的 bug**（TA 今天还在啃前言），用户已在台账里登记；工作量小（一个 `_strip_gutenberg` 函数 + 词表 + 用例）。

**影响面**：`library.py`（+ `corpus.py` 词表）；**只影响 txt 解析路径**，epub 路径零改动；已有书进度不受影响（`reading_state` 书签按章节序号，剥头后章节序号会变——**这是需要动工时仔细处理的一个点**，见风险）。

**风险**：中低。主要风险是「已读古腾堡 txt 的书，剥头后章节边界变化 → 书签错位」。缓解：剥头逻辑只在解析层生效，`reading_state` 存的章节号若超界有 clamp（`trueread.py` 有 `min(chapter, len-1)` 类保护，**未逐行验证**，动工时核对）；最坏情况是某本书重读一章。

**外部依据**：gutenbergr（R 生态处理 Gutenberg 文本的权威包）提供 `gutenberg_strip()` 专门函数剥离头尾（https://rdrr.io/cran/gutenbergr/man/gutenberg_strip.html；源码 https://rdrr.io/cran/gutenbergr/src/R/gutenberg_strip.R）——证明「剥 `*** START/END` 标记」是该生态的标准做法。⚠️ 本会话 web_fetch 被沙箱拦截，未能读取函数实现细节；标准分隔符 `*** START OF THE PROJECT GUTENBERG EBOOK ... ***` / `*** END OF ... ***` 的存在性由搜索摘要与项目自身台账描述交叉印证，**动工时以实际书源文件为准**。

## 1. 收敛：选定候选 A（断线重连）+ 顺手带上 C（古腾堡剥离）

**推荐主线 = 候选 A**，理由：
1. **用户已登记**：需求池 G 模块明明白白写着「断线重连提示 · 待做」，原文就是用户的验收语言（「要能自动重连并给提示，而不是干等」）；
2. **痛点频率最高**：服务器每次 `sync-to-server.sh` 同步都重启服务（AGENTS.md 〇 节流程 = 双推 → 服务器拉 → 重启 → 自检），手机端每次都经历「死页面」；移动端三部曲（v0.107–109）刚收尾，这是移动体验的最后一洞；
3. **工程量最小、风险最低**：单文件前端改动，不动 .py、不动数据、不动接口；
4. **外部做法成熟**：退避重连是网络客户端的通用模式（见候选 A 依据）。

**顺手批 = 候选 C**（可作为同批次的第二项或下一批）：
- 正在流血（TA 今天还在啃前言），用户已在台账候选池登记；
- 与 A 同属「小步、可回滚、不改数据结构」的体验期口径（`docs/体验优化清单.md` 末节）；
- 工作量小（~1 个解析函数 + 词表 + 1-2 个用例）。

**候选 B（CI）建议排后**：价值真实但**不紧急**——CI 的本质是防回归，而项目当前测试纪律已经很强（AGENTS.md 硬闸门 + 30/30 全绿记录）；且 CI 落地有外部依赖核实需求（action 维护状态、3.14 可用性）和时区敏感用例的预期修复工作，适合作为独立批次安排，不与 A/C 混批。**建议作为 v0.111 或紧随其后的独立批次**（需求池 G 模块的另一条待办，与 A 同属用户登记项）。

**候选 D 明确不做**（见 §3 scope cut）。

| # | 步骤 | 改哪个文件/函数 | 为什么 |

| **消息队列/未读补偿后端机制** | `poll()` 的 `after=lastId` 增量拉取天然支持补拉，零后端改动就能实现「恢复后补齐」——不需要任何服务端改动 |
| **发送失败自动重发** | 自动重发有重复消息风险（服务端已收到但响应丢失）；回填输入框+用户手动重发是安全默认。若实测发现高频需求，后续再议 |
| **古腾堡剥离扩展到 epub** | epub 已有 `EPUB_FRONT_JUNK` 判废机制（`library.py:289-300`），不重复造轮子 |

| **改任何 .py 业务代码（候选 A 部分）** | A 纯前端。**worker1 纪律：本角色不改业务代码**——实施由后续批次/worker 执行 |

## 5. 风险与回滚

| 风险 | 概率 | 缓解 | 回滚 |
| --- | --- | --- | --- |
| A：退避逻辑写错导致轮询完全停止 | 低 | 自调度模式（`setTimeout` 链）比 `setInterval` 更可控；A7 断言存在性；手工验收清单第 3 条覆盖「杀进程→重启→恢复」全链路 | revert `web/index.html` 单文件 |
| A：横幅与现有 UI 打架（遮挡输入区/消息流） | 低 | 横幅 absolute 定位在顶部状态区，不动布局流；≤520 移动端实测（项目已有手机实测习惯） | 同上 |
| C：存量书书签错位 | 中 | C5 步骤核对 clamp；最坏重读一章（体验损失可接受）；**动工时先在本地库实测一本已读的古腾堡书** | revert `library.py` + `corpus.py` |
| C：非古腾堡 txt 误剥（标记误匹配） | 低 | 标记正则锚定 `*** START OF ... EBOOK` 全模式（不是裸 `***`）；C4 用例含反例（无标记的普通 txt 不剥） | 同上 |
| 文档/版本号 | — | 按流程：`docs/需求概要` 版本记录 + 需求池 G 模块「断线重连提示」状态改 ✅ + `docs/体验优化清单.md` 落批记录 + AGENTS.md 当前进度（如模式变化） | — |

**回滚总原则**：A/C 均为小步独立改动（A 单文件、C 两文件），任何一处翻车单独 revert 不牵连另一处。
