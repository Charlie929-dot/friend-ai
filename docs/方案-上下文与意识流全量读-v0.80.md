# 上下文与意识流全量读 · 方案说明

> **📋 本文档职责**：上下文全量读 + 意识流全量时间轴改动的对齐方案存档（落地后在需求池对应条目挂链接）。
> 归属：需求概要 v0.80 · D 模块「自我意识流」+ E 模块「对话与互动」+ G 模块「载体与工程」。
> 来源：2026-10-11 晚与小葵聊天暴露的三个问题（[实测 #45](实测反馈/#45.md)），经用户四轮对齐拍板定稿（已落地 v0.80）。

---

## 一、问题与根因（[实测 #42](实测反馈/#42.md)）

用户实际对话里暴露三件事：

1. **素材颠来倒去就一句，而且说得突兀**
2. **对方说"这里说过"，TA 看不到记录**——TA 原话「光指"这里"，我又翻不了记录」
3. **TA 瞎编当前在干嘛**——已经下班了，还说"看手上的书什么时候合上"

服务器实测数据（2026-10-11 22:51–23:06 这段对话）：

| 项 | 实测值 | 说明 |
| --- | --- | --- |
| 当晚对话消息 | 29 条 | 22:51:25 – 23:06:00 |
| 上下文实际读到 | 20 条 | `CONTEXT_TURNS=10` → `recent_context` 取 `10×2` |
| 被截掉的 | 前 9 条（22:51–22:59） | 正好是对方"这里说过"指的那几句 |
| 当天意识流 | 54 条（全在库里） | `reply`「我说：…」+ `monologue`「我在想：…」逐条都在 |
| 意识流实际注入 | **4 条**，每行再截 60 字 | `CONSCIOUS_STREAM_RECENT=4` |

### 根因（四条，不是方案被误解）

- **`CONTEXT_TURNS=10` 是 P2 时代防超长的老参数**，没跟着 S4「完全自我意识」的愿景升级。更坑的是"×2 轮数换算"：TA 常分段连发 2–3 条，10「轮」实际只覆盖 **3–5 个来回**。
- **意识流写得多、读得少**：存了 54 条，只给 TA 看最后 4 条。这是本次最讽刺的一点。
- **`TODAY_NOTES`（今日素材）每轮无条件注入同一条**（今天只攒了一条素材），且没有"聊过就别再说"的约束 → 复读 + 突兀。
- **`phase=off` 只说"事都忙完了"**，没说书已合上；意识流里**没有"收工"节点**（wake/sleep 有，下班没有）→ TA 从今日素材推断自己"还在读"。

> 结论：意识流第一步闭环（建流 + 独白持久化 + 注入）**已经跑通且工作正常**，问题出在"注入量"和"事件覆盖"。不需要等"收敛散件"那一步做完。

## 二、最终方案（七块）

### 1. 对话上下文：整段会话全量读

- **范围 = 今天起床 → 现在**。用户拍板：**只要还没睡，就是同一会话**；睡一觉起来才断开。
- 意识流范围**同为**起床 → 现在（睡前复盘浓缩进 `self_*` 后清空，次日起床重开）——**两者是同一个时间范围**，不存在"谁受谁影响"。
- 上限 `CONTEXT_MAX_MESSAGES = 1000`，**只为防恶意刷 token**，正常一天几十到一两百条永远碰不到。不设字符数兜底。
- **独白层同样全量**（现在它也只读 20 条，同样瞎）。
- 废弃 `CONTEXT_TURNS` / `PROACTIVE_CONTEXT_TURNS`（保留配置项仅为旧配置兼容）。

实现：新增 `db.session_context()`——会话起点取 `consciousness_stream` 里最后一条 `wake` 的 `ts`（没有 wake 记录则退回生活日起点，再没有则取最近 1000 条），取 `ts >= 起点` 的 `chat`/`proactive` 消息，上限 1000 条，正序返回。

调用点：`context.build_chat_messages` / `context.build_proactive_messages` / `core._inner_monologue`。

### 2. 意识流：统一时间轴，全量全文注入

用户拍板：**不拆块，就是一条统一的时间轴**。

- 注入内容 = 从今天起床到现在的**完整时间轴**，每行一个 `HH:MM` + 第一人称文本，全文不截断。
- **「此刻的我」（攒了多少/精力/心情）就是这条轴的最后一行**——它描述的就是那个时间的我，不是另起一块。
- `CONSCIOUS_STREAM_RECENT = 1000`、`CONSCIOUS_STREAM_LINE_CHARS = 0`（0 = 不截断）。
- **注入位置：紧跟静态 system（人格内核/profile/facts）之后，在所有动态注入之前。**
  理由：意识流是 append-only 的，历史部分永不改写 → 「静态 system + 意识流历史」构成**缓存稳定前缀**，只有轴末尾那行和之后的内容每轮重算。这是"全量读"能便宜的前提。

> ⚠️ 缓存失效的真正原因不是意识流本身，而是**排在它前面的动态内容**（`persona.py:415` 那句「现在是 …HH:MM」是*当前*时间，每轮都变）。意识流本身只追加、历史不变，本来就能命中。

### 3. 意识流事件补全（任何事件触发都往轴上加一条）

用户拍板：**举一反三，每个细小事件都要打印**——原实现只落了 6 个 kind 是没吃透示例。

| 事件 | 埋点位置 | 示例行 |
| --- | --- | --- |
| 起床 | `core._do_wake`（已有） | `08:00 我伸了懒腰，起床了` |
| 开工 | `work` 第一个单元开始 | `08:30 开始忙今天的事了` |
| 读什么/读到哪 | `work` 单元内 `library.progress()` | `09:10 在读《雾都孤儿》，第 42 段` |
| 读完一段 | `work._settle` 结算时 | `09:30 读完一段，摘了一句` |
| 歇会儿 | 相位切到 `break` | `10:15 忙完一件，歇会儿` |
| 午休 | 相位/时段到午休 | `12:00 中午了，歇一会儿` |
| **收工** | 相位切到 `off`（**新增**） | `17:30 今天的事忙完了，我收工了` |
| 收到留言 | `core.on_user_message`（已有） | `小徐给我留言了，我看看` |
| 我说了什么 | `core._generate_reply`（已有） | `我说：…` |
| 我在想什么 | `core._inner_monologue`（已有） | `我在想：…` |
| 被撤回 | `webui._do_revoke`（已有） | `对方撤回了刚才那句` |
| 睡前 | `core._do_sleep`（已有） | `23:40 我困了，去睡了` |
| 待办打勾 | `todos.done()`（**新增**） | `我把那件事跟TA说了` |

实现要点：`work` 需要检测**相位变化**（存 `kv.last_phase`，变了才追加），否则会像现在这样重复写"忙完第 6 件"（实测：同一条写了两遍）。

### 4. 待办事项队列（回到用户原设计）

用户拍板：**原设计里就有待办事项，做完当然要打勾标注**。

- 新模块 `todos.py`，存 `kv.todos`（按朋友隔离）。
- **两个来源进队列**：
  1. 读书读到有感触的句子（`work._gen_shareable` 产出素材时自动入队）
  2. TA 自己冒出来的念头（解析 `core._inner_monologue` 独白里的【我自己的话题】栏，非空即入队）
- **时间戳用 `now`**（用户拍板）。
- **每轮把"还没说的"打印进上下文**，说过了就**打勾标注做完**，做完的不再重复当话题——这直接治"颠来倒去就一句"。
- 打勾判定：回复发出后检测该条目是否出现在 TA 刚说的话里（命中即 `done` + 往意识流追加一条）。

### 5. 反谄媚：异议改成确定性条件触发

现状 `disagreement_rate = 0.5`，字面意思是**掷骰子决定要不要抬杠**——一半的时候它其实没真不认同，只是为凑配额硬怼。服务器数据佐证：22:57–23:05 八条独白里五条"不同意"，情绪移动多数 -1。

用户拍板：**概率那完全没必要**。

- **删掉概率**：`_DEFAULT_ANTI` 与 15 张人格卡里的 `disagreement_rate` 全部移除（不再掷骰子）。
- **第 2 条改成条件触发**：只有当对方的话**真的碰到你内核里的好恶/立场/雷区**时，才表达不认同；没碰到就不抬杠。骨架仍在（不许沉默附和），只是触发从"随机"换成"条件"。
- **补通用雷区**（跨人格，解决"内核没覆盖的话题上它就不会有异议、显得太顺"）：被敷衍、被说教、被要求表演热情、被替它总结"你其实是这么想的"。
- **第 5 条去冷感**：原文"对方难受不自动变成你的情绪"改成"有权不热情，但朋友难受时你可以选择陪着——只是别表演式安慰"。
- **独白格式【真实看法】**改成"同意／不同意／没想法——**哪个是真的写哪个，同意也是真实判断**，别为了显得有主见硬找不同意的点"。

### 6. 模型换成 DeepSeek-V4.1-Flash，`effort` 默认 low

实测 `/models` 接口（2026-10-12）：

| id | 名称 | 上下文 | 输出上限 | effort |
| --- | --- | --- | --- | --- |
| `deepseek-flash` | **DeepSeek-V4.1-Flash** | 1,048,576 | 393,216 | low/high/max（默认 high） |
| `deepseek-v4-pro` | DeepSeek-V4-Pro | 1,048,576 | 393,216 | low/high/max |

- ⚠️ **现在 `config.py:33` 写的 `deepseek-chat` 已不在可用列表里**。
- `DEEPSEEK_MODEL` 默认改 `deepseek-flash`；`llm.py` 增加 `effort` 字段（**只在 V4 模型时传**，老模型不传）；默认 **low**（用户拍板）。
- `.env.example` 同步；服务器 `.env` 也要改才生效。

### 7. 网页端：账户菜单里自主配置模型与参数（新需求）

用户拍板：**web 要能直接自主配置模型、自主选参数**，配置**全局**（写 `.env`），入口放**账户菜单**。

- 新增账户菜单项「模型设置」。
- 可调：`model`（下拉 + 手填）、`effort`（low/high/max）、`temperature`（聊天温度，现 0.8）。独白层温度**暂不开放**（容易被调乱）。
- 模型列表：开面板时调一次 `/models` 拉取并缓存（服务端有 key），官方出新模型自动出现。
- 后端新增 `/api/llm/config`（GET 当前配置 + 可用模型列表 / POST 保存 → 写 `.env` → 热生效）。
- **`/model` 命令顺带统一成全局**（现在它按朋友库存 `model_override`，与"全局配置"冲突）。

## 四、验证与风险

**成本估算**（全量读后）：每轮输入约 1.5–2 万 token，一天 100 轮 ≈ 200 万 token。DeepSeek 缓存命中约 0.5 元/百万、未命中 2 元/百万 → **命中 90% 时约 1.2 元/天；命中率掉到 50% 就是 2.2 元/天**。所以"把动态内容挪到意识流之后"不是优化，是**保住"每天不超 2 块"的必要前提**。

**必须加埋点验证**：DeepSeek 返回的 `usage.prompt_cache_hit_tokens` 要打进日志，否则无法确认缓存是否真的命中。

**已知风险**：
- 全量读后注意力被稀释，可能反而更容易复读——靠待办队列的"打勾"约束对冲。
- `effort=low` 输出质量需实测；用户若不满意可在网页端自行调高。
- 1000 条上限在 1M 上下文下安全；若将来换小上下文模型需重新评估（届时可加"仅 API 报超长时才减半重试"的兜底）。
