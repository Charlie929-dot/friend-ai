## 0. 诊断：七个症状，一个根子

10-13 实测的七条症状（见 v0.87 §0）不是七个 bug，是同一个架构病的七种发作：

> **TA 的「生活」不是一条时间线，而是四本账（`work_state` / `trueread_plan` / `trueread_cursor` / `reading_progress`）+ 三套钟（`SCHED_*` 固定时钟 / 人格锚点 / offline 起床推算），靠「同步 + 注入」拼成体感。**

| 症状 | 发作机理 | 本方案的修法 |
| --- | --- | --- |
| 1 起晚 10 点才醒 / 排班脱节 | 时间在 N 处各自推算、各自解释「醒没醒」 | `life.today()` 唯一推算 + 醒来事件落日志（排查从法医变看一行） |
| 2 「攒了 X 块」机械没意义 | **prompt 念账本**——把币种换成「经验」只要还在念数字，就还是那句机械话 | 数字给屏幕、事件给舌头（§5） |
| 3 「车怠速」连发 4 条 | random 无弹药时放 LLM 自由发挥编环境 | 自由发挥路径**删除**，无弹药不发（§6） |
| 4 连发间隔看上一句 | 索引差一位 | `segments[i-1]` → `segments[i]`（§7） |
| 5 目录细线不醒目 | UI 颜色 | 调亮 `.l1`（§7） |
| 6 「第 801 段」卡住 / 读前言 | **三个进度真相靠同步**，同步就会失步 | 一个书签 `reading_state`，删跳读、删同步（§4） |
| 7 两套时间参数不联动 | 排班被发明了两次（工作单元 / 半节作息） | `SCHED_*` 整族退役，节奏 = 章节边界 + 精力（§3） |

v0.87 r2 治的是「账怎么记更合理」；本方案治的是**「账本就不该有四本、数字就不该进嘴」**。

## 2. 设计原则（四条，全案贯彻）

1. **一条时间线**：TA 的今天 = `life.today()` 一个 Day 对象 + 一条 append-only 意识流。钟只在这里敲。
2. **事件是源，数字是视图**：进度/经验/精力全是派生投影；发生的事（起晚/读完一章/被触动/收工）才是本体。
3. **章节边界是节奏**：真人读书歇在章末，不歇在铃响。时长自然变化（40–120min 会话），不需要网格。
4. **删除优于合并**：两套时间参数的根治不是面板合并，是让其中一套消失；三处进度真相的根治不是同步，是让其中两处消失。

## 3. 生活引擎 `life.py`（核心重写，`work.py` 退役）

### 3.1 Day 对象：唯一的钟

- `life.today(now)` → `{day, wake, start, sessions[], bedtime, plan{…}, flags}`，**醒来那一刻排定、落 kv、当日只读**（保留现有「醒来才排、同日幂等、惰性补账」哲学，`work.py:132-151` 的骨架平移）。
- **起床推算只此一处**：`offline.today_wake_at`（人格锚点 + 赖床浮动，`work.py:80-88` 的 `_wake_point` 平移进来）。webui/core/stream/work 消费方不再各自问「现在几点我醒没醒」。
- 醒来 / 起晚 / 开工 / 读完一章 / 收工 / 读得晚——全部作为**事件**落意识流。再出「为什么 10 点才醒」，翻一行 `wake` 日志即有答案（§8）。

### 3.2 会话排定（醒来时一次性算好）

```
t   = wake + 磨蹭(WORK_WARMUP_MIN, 带抖动)
队列 = 当日圈定章节(trueread.plan 平移, §4.1)
while 队列 and t < bedtime:
    贪心合并队列头部的章, 直到累计字数 ≥ NOMINAL_SESSION_MIN(40min)×速度 或队列空
    session = {chapters, start: t, end: t + 累计字数÷速度}
    if end > bedtime: 标记 partial=True(读到睡前, 明日重圈) → 收进列表, break
    t = end + 休息(会话长度×系数 + 精力加权 + 抖动; 跨 NOON_HOUR 的那次 ≥ LUNCH_MIN)
```

- **速度 = 常数**（推导：`READING_DAILY_CHARS ÷ 320`，320 = 名义日阅读预算，代码常量不进 config）。**不从「剩余时间」反推**——起晚 → 时间窗变短 → 读得少或读得晚，零特判（这是拍板 #2「不追进度」的结构化落地）。
- 章长本身 2k–15k 字 → 会话自然 40–120 分钟不等；短章贪心合并防「16 分钟读一章歇一次」的碎片感。
- **睡前是唯一硬边界**；`bedtime` 沿用 `_bedtime`（人格睡觉点，`work.py:61-66` 平移）。

### 3.3 进度与经验（拍板 #3/#4/#7 落地）

- **进度** = 已读字数 ÷ 当日圈定总字数；已读字数 = Σ「[排定起点, now] ∩ 各会话窗口」× 速度（partial 会话截到睡前）。纯派生，不落库。
- **经验 = round(进度 × 100)**，当日进度 100% 才满经验 100；收工时意识流记一笔「今天攒了 X 点经验」。
- 跨日累计：本次不做（数据已在意识流/日记，后补不返工）——v0.87 待确认点 #2 维持「先当日」。
- 简化决策（明说）：已读分钟按墙钟累计，**聊天打断不扣除**——打断的代价由打断成本（cost）与精力叙事承担，进度只是被推后（与旧单元制行为一致，不新增机制）。

### 3.4 起晚 / 读得晚 / 收工（拍板 #2/#5 落地形态）

- **起晚**：排定时 `wake` 晚于人格锚点 → `stream.once("late_wake")` 记「今天起晚了」；之后一切照常（锚点后移 → 窗口压缩 → 少读或读得晚，无特判代码路径）。代价形态：夜猫子人格多半表现为「读得晚」而非「读不满」——都是自然出现的代价，不特判、不归因（红线 #5）。
- **读得晚**：`LATE_READ_HOUR`（新参，默认 20 点）之后仍处于会话中 → `stream.once("overtime")` 记「今天读得晚」一次。这就是拍板 #5 的「加班」。
- **收工**：进度 100% 或到睡前 → `off`，记「今天的事忙完了，攒了 X 点经验」。

### 3.5 精力（拍板 #6 的另一半）

`WORK_ENERGY_MAX/COST/RECOVER` 保留，语义换算为**每分钟率**：消耗率 = `COST ÷ 40`（名义会话时长）、恢复率 = `RECOVER ÷ 20`（名义休时长），会话中按分钟耗、休息中按分钟回。`cost.fatigue(energy)` 读整数精力，**零改动**。

### 3.6 phase 契约不变（消费方零改动的保证）

**phase 键集合不变**：`idle / working / flow / break / off / sleep`——会话内前 `WORK_FLOW_RATIO` 段 = `flow`、其余 = `working`；会话间 = `break`；排定起点前 = `idle`；收工/无书 = `off`；未醒 = `sleep`。已核实消费方（v0.87 r2 §2.2）：`cost.py:67-73`、`mood.py:49-58`、`offline.py:31,49,57,129`、`tone.py:34` 只读 `phase/flow/energy` → **四文件各改一行 import，其余零改动**。

### 3.7 状态存储：两本账，零同步

| 账 | kv | 内容 | 取代的旧账 |
| --- | --- | --- | --- |
| **今日生活** | `day_state` | `{v:2, day, wake, warmup, sessions[], energy, exp, settled_idx, plan{book_id, chapters, total_chars}, overtime}` | `work_state`（units/money）、`trueread_plan` |
| **书签** | `reading_state` | `{book_id, ch_idx}`（书级游标，只被章节结算推进） | `trueread_cursor`、`reading_progress` |

- 进度、在读章、已读字数、phase 全部派生不落库（状态比旧 `units` 列表更小）。
- **兼容策略**：读到 v1 旧账（units/money/cursor/progress）一律忽略重排当日。自用阶段不迁移，代价 = 一天叙事。
- `work.reset()` → `life.reset()`；`work.plan()` → `life.sessions()`（返回排定窗口，测试锚点用）。

## 4. 阅读单真相（`trueread.py` 瘦身重写 + `library.py` + `reading.py` 退役）

### 4.1 圈章与书签

- 圈章逻辑（`_book_order` 人格两级偏好排序、`_next_chapters_from` 整数章节宁少勿超，`trueread.py:85-118`）**平移保留**，从 `reading_state.ch_idx` 起圈（书级游标，跨天不重置——v0.88 R1 断裂① 就此结构性消失，不再需要「段落 idx 估章节号」的换算 `trueread.py:158-167`）。
- 未读完的圈定章（partial）不结转额度：次日从 `ch_idx` 重圈当日字数——「不追进度」。

### 4.2 章节结算（会话即章节组，入口唯一）

- **会话按章节边界排定 → 章末就是会话末**，触发判定零成本：一个会话结束，结算它包含的每章（纯派生，无 LLM）。
- 结算动作（LLM，后台）：沿用 `settle_chapter`（思考 buffer + 章节节选 → 短概述/完整转述/打动）→ 读书笔记 alpha/beta + 向量索引 + 打动进素材池/待办。
- **互斥与冷启动**（吸收 v0.88 R2）：串行后台队列，同时只跑 1 个（复用 `_generating` 同款闸门），深度 ≤3；更早跨过的章只推 `settled_idx` + 意识流记一笔，不补笔记（防冷启动 LLM 尖峰）。
- **幂等**：`settled_idx` 是唯一事实，结算成功才推进；在读章 = 派生（第一个累计边界 > 已读字数的章）。
- **泛化素材退役**（吸收 v0.88 R3）：`_SHARE_PROMPT`/`_produce_shareable` 的 article=None 路径整条删除，素材只来自章节结算的打动。无书 = 无素材 = random 主动消息自动跳过（与 §6 闭环）。`interests.record` 的 genre 信号改从章节结算取（书的 category）。

### 4.3 换书与笔记判重（吸收 v0.88 R1 断裂③）

- 书末（`ch_idx` 越界）→ 从偏好排序取下一本，意识流记「《X》读完了，翻开《Y》」；给 v0.88 R4「全书总结」留触发点（接口：换书事件）。
- `reading_notes` 加 (book_id, chapter) 判重约束——治同章笔记日复一日落库。

### 4.4 epub 非正文页过滤（拍板 #11 前半，治「还在读前言」）

`library._parse_epub`（`library.py:341-362`，spine 全量进 chapters、无过滤 ✓）：**关键词**（title page / 版权 / copyright / 目录 / contents / Standard Ebooks / producer…）**或**（`char_count` < 600 且位于书首前 5 个 spine 项）。词表进 `corpus.py`（与 `SUBJECT_JUNK` 同款先例，约定 #3）；短章≠非正文（诗集），小字数必须叠加「书首」位置条件。

### 4.5 跳读退役（拍板 ①②）

删 `library.next_passage` + `library.progress` 写路径 + `work._settle` 跳读分支 + `reading.py`（内置书摘语料留档不动，模块退役）。真读是唯一路径；书架空 = 当日无任务（`plan.done` → `off` + 意识流记「书架上没有想读的了」）。

## 6. 主动消息：自由发挥路径删除（拍板 #8，治「车怠速」×4）

- **random 场景 = 从待办/素材池/承诺/兴趣/旧记忆里取一件真实的事说**；`context._inject_random_topic`（`context.py:189-223`，现三源皆空时静默落空 ✓）改为返回 bool，五源（含 `selfmem` 承诺）皆空 → `build_proactive_messages` 返回 None → core **不调 LLM、不发**。定性为**删除一条路径**，不是加闸门。
- `persona.PROACTIVE_SCENARIOS["random"]`（`persona.py:321`）删「刷手机看到的东西」（邀请编造），保留「正在读的书、聊到一半的事」。
