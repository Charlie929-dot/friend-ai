## 0. 本批目标

把批 2 建好的源层（`sources.py` + `info_items` 表）**接进它的日常**——做完这一步，人设第三件事「刷手机看信息」才第一次在对话里真的看得见（此前只能靠手动 `/browse` 触发）。

**验收**（承 §9 批 3 原文）：

1. 注入块**只在有 items 时出现**（空表必须不出现）；
2. 刷到的**能被主动提起、且同一条不重复提起**。

**本批不做**：

- 搜索引擎 provider（仍为 `none`，属批 4）；
- 对话工具 `lookup_online` / `open_link`（批 4，SSRF 六例也在那批）；
- 记忆咬合三条闸门 + `vecindex` 加 `source="info"`（批 5）；
- `INFO_ITEMS_KEEP_DAYS` 表清理窗口（§6.3，写在第 6 节记忆咬合里，**归批 5**）。

### 1.1 一条关键口径更正（本轮核实所得，勿再混淆）

**意识流本来就包含聊天**——`core.py:107` 写入「XX说：…」（对方消息）、`core.py:256` 写入「我说：…」（TA 回复），另有 `inbox`（离线留言）、`monologue`（内心独白）。这属**统一事件源**（v0.84 §5 拍板 #6①），**已落地、无欠账**。

- 因此 §5.4 要加的 `stream.append("browse", ...)` 是给意识流**加一个新的事件种类**（TA 的一天里多一件「刷了会儿手机」），**不是**"把聊天补进意识流"。
- **"收敛散件"（[方案-自我意识流-v0.55.md](./方案-自我意识流-v0.55.md) §5）与此无关**——那是把 `work/mood/selfmem/独白` 四处**散注**收敛成一条流，是另一件事。

### 2.1 注入块与弹药的措辞要点

- **注入块视角 = 它自己的视角**：「【我今天刷到的】」——**不是**"帮你查的"（§12 一视同仁红线）。这一块的动机永远是「我今天刷到过这些」，不是「为了你去找」。
- **块内自带的负约束**（§0 红线的守护点）：明写"这一块里有什么，我今天就真的只刷到了这些；没有这一块 = 今天没刷到什么，**别把不知道的东西说成「我刚刷到」**"。
- **弹药措辞**：落在具体内容上，与现有素材池那支同款"别泛泛、别硬扯生活"的分享质量要求。

### 2.2 已知边界（写下来防"忘了"）

- `WORK_ENABLED` 关掉时 `life` 没有相位 → **不会自动刷**（手动 `/browse` 照常可用）。
- `BROWSE_ENABLED` 关掉时：不自动刷、不注入、不弹药（面板开关即"回归今天行为"）。
- 你不订阅的方向，TA 就永远"培养"不出相关兴趣；你订了某方向的源，TA 会慢慢对该方向有劲——这是"见得多就有劲"的本意，但**源单会影响它的偏好漂移**，属已知设计（非缺陷）。

## 4. 两处决策（本批对齐产生，需在文档留痕）

### 决策 A：兴趣累加代码放**调用方**（偏离 §5.4 原文）

- §5.4 原文写「`daily_pass` 里对每条 Item 用 `INTEREST_TOPICS` 词表跑 detect」。
- 但 `sources.py` 开篇即声明「**不知道自己被谁调用**」、第 21 行明示「**不 import 业务模块**」。把 `interests` 塞进 `daily_pass` 会破坏这条架构约定。
- **定稿**：累加放 `life` 的刷信息钩子（调用方）——刷完读 `items_today()` 里新增的 id（取刷前 `max(id)` 做差），再喂 `interests`。`sources.py` 保持干净。

### 决策 B：聊天源**保持现状**，只作待议项记录

- 现状：`interests.detect()` 要求 `INTEREST_SIGNALS`（"感兴趣/有意思/入坑"等 17 词）**与主题词共现**才 +1——即"TA 自己说出口才算"。
- 本轮讨论中出现过「交流中出现过的主题词数都计入」的说法。**定稿：聊天源代码不动**，把「聊天源是否该放开为『聊到该主题即 +1』（去掉信号词门槛）」**仅作为待议项记录在本方案**，**不在本批落地**。
- 待议项原文：*聊天源当前要求"信号词 + 主题词"共现；是否改为"交流中聊到该主题即计入"（与刷源共用同一套交流主题集），待后续单独确认。*
