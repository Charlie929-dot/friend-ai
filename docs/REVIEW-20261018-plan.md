### 3 遗漏（并发与锁 / 数据迁移与兼容 / 测试覆盖 / 服务器与本地 / 其他）

**并发（A 的 poll 自调度）——判定：半优点、半遗漏**。`poll()`（`web/index.html:1479-1491`）目前**没有任何 in-flight 保护**，`setInterval(poll,900)` 在请求 >900ms 时本就重叠执行；改成 `setTimeout` 自调度链反而天然串行——**改法本身更安全，是优点**。但方案既没声明这个动机，也没防自调度的特有失败模式：`setInterval` 永远重试（吵闹的失败），自调度链一旦在异常路径漏排下一次 = **静默冻结**（页面看似活着、永不更新），故障可见性比现状倒退。必须补实现约定：`schedulePoll` 的下一次调度放 **finally**；`send()`/`sendText()` 内直调 `poll()` 的两处（:1706/:2459）统一走调度入口防双跑；别动 :2567 的 `loadMemories` 计时器。

**数据迁移与兼容（C 的存量书签）——比方案预估重一级**。方案 C5 说最坏「重读一章」；实际：走字数 fallback 的存量**英文书**剥头后章节总数会变少，`trueread.py:197-208` 的 `advance()` 在 `nxt >= len(chs)` 时**直接换下一本书并往意识流写一条假的「《X》读完了，翻开《Y》」**——误判读完换书 + 污染自我叙事，不是重读一章。`plan_from` 的 clamp（:112）只护入口、护不了 advance 路径。风险面可收窄：中文正则书剥头只删章前内容、「第X章」标记数不变、**书签零风险**；真正受影响的只有 fallback 书。

**测试覆盖**。A7（断言进既有用例、92 不变）与 C4（新用例、92→93）各自成立；但 §2 表头写「EXPECTED_TOTAL 不变」、C4 又写「92→93」——**字面矛盾必须点出**：细读是两个作用域（前者管 A、后者管 C 且自带「若 C 并入」条件），但方案没在 §2 注明分轨计数，且 §1 说 C「可作为同批次的第二项**或下一批**」骑墙未钉死——读者无法确定终值是 92 还是 93，worker2 无从实现。要求：拍板 C 并入与否，删掉骑墙表述，EXPECTED_TOTAL 终值随批构成写死。

**服务器与本地**。验收无 sync + 真机环节（见维度 1）；且 TA 正在啃的那本古腾堡书在**服务器库**——剥头修复上线后要确认服务器侧同书生效，C 的验收第 2 条只写了本地放书。

**其他（A5 回填 × 响应丢失）——方案完全未写的实锤交互**。`send()`（`web/index.html:1686`）在 :1689 **先清空输入框再发**，失败时文本已丢——回填确实是修复；`sendText()`（:2446）只是表情面板支路（:2433 调用），**A5 只点名 sendText 漏了 send 主路径**。更重要的：`/api/messages` 增量接口**不分 role**（`webui.py:277-305` 调 `db.messages_page`；`db.py:326-334` 的 WHERE 只有 `kind IN ('chat','proactive','notice') AND id > ?`，无 role 过滤——本轮已复核）——「服务器已收到、响应丢失」的消息会被下一次成功 poll 用 `after=lastId` 拉回来正常渲染；此时 A5 又把同文本回填进输入框 → 用户看见消息「回来了」+ 输入框还有原文 → 手动重发 = **重复消息**。方案只挡了自动重发，没挡这条。修法（纯前端几行）：catch 里先 `await poll()` 一次，若同文本 user 消息已被拉回则不回填、改提示「已送达，响应丢了」。

**批构成与回滚粒度**。A/C 混批本身不违反体验期「小步、可回滚」口径（先例：v0.108 一批 5 项不相关小修、v0.109 一批两件不相干事）；但方案 §5 承诺「任何一处翻车单独 revert 不牵连另一处」——**单 commit 做不到**（v0.109 恰是单 commit 反例 7d06210）。要求拆两个 commit，让承诺在版本历史上可执行。
