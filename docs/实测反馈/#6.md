# 实测反馈记录 #6（2026-10-07，群聊记忆丢失）

**Bug：群聊记忆提取报错 `table memories has no column named source`，群聊内容全丢**

- 现象：阿燃那里开的群聊散群后，切到"初遇朋友"私聊，后台提取记忆报 `no column named source`；初遇朋友说"群聊我还真看不到，只记得咱俩单独聊的"——群聊记忆一条没写进去（当时所有库 source='group' 记忆均为 0）
- 根因：信息调度层给 memories 表加了 `source` 列，但**旧归档库**（加列之前创建的 friend-<id>.db）没有这列；切库（/friend 复制回、群聊散群写回/提取）后，`add_memory(source=...)` 的 INSERT 带 source 列 → 缺列报错
- 修复（2026-10-07）：①**切库时自动迁移**——/friend 复制回、群聊散群写回/提取前各调 `db.init()` 补列（幂等）；②新增 **/rememgroup 命令**——把 messages 里 kind='group' 的群聊记录重新喂给提取器、写 source='group' 的记忆（断点续跑），补救历史遗漏；③已主动迁移现存旧库 + 补提取（小葵 120 条、初遇朋友 28 条、阿燃若干）
- 附带修复：①回应线程 respond_done.clear 移进锁内（修偶发"轮次硬顶失效"竞态）；②焦点交接后普通消息不再沿用残留短阈值误触发闲聊
