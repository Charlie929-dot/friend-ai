# 实测反馈记录 #24（2026-10-09，情绪状态解冻 + 需求池账目拆清）

**背景**：需求池里「打断成本机制 + HUD」这条标了 ✅，说明末尾却还挂着"剩余：离线留言、HUD 心情维度（情绪状态仍搁置）"——状态和说明打架。用户指出来后，两个动作一起做：①解冻情绪状态、落地心情维度；②拆条 + 全文档体检。

**设计①：心情 ≠ phase ≠ 打断成本，是第三个视角**

- 三个词都从 `work.status()` 拿数据，但回答的问题不同：phase 答"它在干嘛"（客观）、打断成本答"现在找它的代价多大"（边界，落到"有空/还行/正忙"）、心情答"它此刻自己感觉怎么样"（情绪，落到"投入/放松/疲惫"）。
- 心情词表是**感受化**的，不是 phase 的机械翻版；再加**时段情绪**（夜深忙完=平静而非轻松）让心情有独立于 phase 的维度。

**设计②：心情由它自己的生活推，确定性可复现**

- 映射：心流=投入 / 忙=专注 / 歇=放松 / 下班=轻松 / 还没开工=慵懒 / 精力低=疲惫 / 深夜忙完=平静。全部惰性推算（和 work 一致），不靠 LLM 每次瞎编，HUD 才稳定可测。
- 精力低**最先**决定心情：累是最强烈的感受，盖过其它。

**设计③：三条红线照做（解冻不破戒）**

- 心情**不围绕任何人转**（它不因为"谁来找它"而开心/难过，只由自己的生活推）——对应「一视同仁」宗旨。
- 心情是**短暂状态，不改稳定人格**（人格漂移是砍掉"阅读修炼人格"踩过的雷）。
- 语态**只描述自己状态**，禁止把心情归因到对方（`corpus.COST_BLAME` 兜底）。

**设计④：拆条标准——每条需求一个状态，说明列不再藏尾巴**

- 把复合需求拆成独立条目，每条状态列要么 ✅ 要么待做，说明列不再用"剩余：…/遗留：…"含糊。
- 全文档体检顺带清掉三处同类问题：日记系统（尾巴"给不给看的人设化拒绝"）、网页端 Web UI（尾巴"断线重连+移动端适配"）各拆成独立待做条目；反愧疚条目那句"剩余部分随打断成本落地"是**假尾巴**（其实已随打断成本做完），直接清理成已完成。
