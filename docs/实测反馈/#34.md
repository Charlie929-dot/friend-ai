# 实测反馈记录 #34（2026-10-10，删除朋友落地）

**背景**：用户建议增加删除朋友功能。两个决策点用户拍板：**先备份再删**、**正在聊的这位不许删**。

**落地**：`/delfriend <编号> yes`。①删前把 `friend-<id>.db` 复制进 `backups/friend-<id>-删除备份-<时间戳>.db`（误删可拷回项目根）；②目标若是当前正在聊的那位 → 直接拒绝并提示先换朋友（`db.get_kv("friend_id")` 与归档文件内的 friend_id 比对）；③不带 `yes` 只返回确认提示，不真删（网页端弹窗已确认过才带 yes，双重保险）；④`archive.log` 追加一行含备份路径。网页端朋友列表每项加红色「删除」，本地先用 `curFriend`（`/api/friends` 的 current）拦住"删当前朋友"，再弹 confirm。

**注意**：编号是 `_archives()` 的顺序（相识时间升序），删掉一位后**编号会重排**——所以删除后前端一定 `loadFriends()` 重取列表，别拿旧编号做事。
