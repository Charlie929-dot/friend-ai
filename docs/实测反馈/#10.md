# 实测反馈记录 #10（2026-10-07，A/B 两级记忆库落地）

**功能落地：B 库长文本 + 伪链接按需展开**

- 需求：用户描述完整记忆架构愿景——"检索到相关的如果是短的就直接提取，长的就有伪链接跳转到 B 库提取"，对应需求池「记忆系统 v3」的 B 库长文本（此前仍待做）
- 落地（2026-10-07）：
  1. **db.py**：新增 `long_memories` 表（B 库，summary 摘要 + content 全文 + 五维标签）；memories 表迁移加 `long_id` 列（0=无长文）；配套 add/get/all/delete/touch/set_status/count 函数，clear_all 一并清理
  2. **memory.py 提取器**：EXTRACT_PROMPT 增加长文输出——"一句两句说不完"的信息（完整经历/深入讨论/详细方案）输出 `long:true + full:全文`，content 仍写一句摘要；`_apply` 分流：长文摘要进 A 库（long_id 关联）+ 全文进 B 库（单条上限 2000 字，全文也过确定性红线），短记忆照旧
  3. **memory.py 召回**：`recall` 加 `expand_long` 参数——默认不展开（只返回摘要省 token），展开时把命中长文的全文附到 `long_content`；新增 `wants_expansion(query)`（判"详细/完整/说说"等追问细节词）与 `expand_long_memory(mem)`（按需取全文）接口
  4. **context.py**：`_memory_line` 对带 long_id 的记忆标注「【有长文，可说「详细讲讲」】」；`_memory_message` 渲染已展开的全文（详情全文）；`build_chat_messages` 追问细节时自动展开
- 效果：长文不再被压成一句话丢细节；召回默认只看摘要省 token，用户问"详细讲讲"时才展开全文。"伪链接"的 AI 主动跳转（TA 自己决定何时查 B 库）留给 MCP tool 阶段
- 测试：新增 test_long_memory（落库分流/伪链接/追问展开/渲染标记），全量 35 项通过
