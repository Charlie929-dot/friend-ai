# 实测反馈记录 #16（2026-10-09，代码 ↔ 需求对齐回归）

**背景**：以「需求概要 v0.30」为准逐条核对代码，找出"文档说一套、代码做一套"的地方并修。以下是这次真正踩到的坑。

**坑①：`BUSY_SIGNALS` 漏一个逗号，"安静"从未生效**

- 现象：corpus 里写的是 `"别说", "不要说" "安静", "stop"`——`"不要说"` 和 `"安静"` 之间**漏了逗号**，Python 的隐式字符串拼接把它们粘成了 `"不要说安静"`。结果"安静"这个忙碌信号从来没被识别过，用户说"安静"不会进静默期。
- 教训：词表是**一行挤好几个字符串**的写法，漏逗号不报错、静默失效，肉眼极难发现。已加断言兜底（`BUSY_SIGNALS` 里不允许出现超长"词"）+ 逐词生效的测试。

**坑②：随机闲聊时段用的是全局作息，与"按人格作息自适应"结论冲突**

- 现象：待确认 #8 的结论是"按人格作息自适应（人格池已有各自作息 + 频率倍率，全局固定会打架）"，代码里 `wake`/`sleep` 两个定时任务确实跟人格走了，但**随机闲聊 `random_chat` 还用 `config.WAKE_HOUR`-`config.SLEEP_HOUR` 全局值**。夜猫子（10 点起、凌晨 2 点睡）会在 8–10 点、22–23 点这些它本该在睡觉的时段被发起闲聊。
- 修：`scheduler._awake_hours(wake, sleep)` 统一按时段生成 cron，**跨午夜拆成两段**（"10-23,0-1"）。顺带修了 `sleep_hour=0`（0 点睡）被当成"睡 0 小时"的边界——按 24 点处理。

**坑③：群聊砍了半年，代码里还有一堆残留**

- v0.27 就删了 `groupchat.py`，但通道层 `send(text, sender="")` / `typing(sender="")` 还留着"群聊模式：带上发言人名字"的分支和注释；日记复盘 prompt 还写着"可能只和一个人，也可能和一群人"；记忆提取 prompt 里举例还是"群里聊了 X"；`.gitignore` 还留着 `group_session.json`。
- 教训：**删功能只删主文件是不够的**，接口签名/prompt 措辞/配置文件里的残留会一直误导后来的人（也包括 AI）。这次一并清干净，并加了签名断言防复发。

**结论**：本文档（需求）与代码的偏差主要来自两类——①新决策落地时只改了入口没改全部分支（作息）；②砍功能时只删主文件没清残留（群聊）。后续建议每次拍板后按 `AGENTS.md` 的对照表过一遍。
