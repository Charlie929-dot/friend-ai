## 二、落点与实现要点

| 落点 | 实现 | 关键约束 |
| --- | --- | --- |
| `life.tick()` 挂点 | `tick(now=None)` 里 `status()` 之后调 `_browse_tick(s, now)` | 判定**只放 tick**、不进 `status()`（后者被 HUD/意识流/成本/每轮聊天路径高频读，会误触发） |
| `day_state` 两字段 | `browse_passes`（当日已刷次数）+ `browse_last_phase` | **只在相位变化时写 kv**、不每分钟写库；`browse_passes` 醒来重排即归零 |
| 后台线程 | 照 `_settle_one`：守护线程 + `_browsing` 互斥标志 | `tick()` 只判定 + 计数，绝不阻塞调度与聊天 |
| `context` 注入块 | 动态区【我今天做过的事】之后加【我今天刷到的】 | **空表则整块不出现**（§0 红线守护点）；不破坏缓存稳定前缀 |
| 主动弹药 | `_inject_random_topic` 素材之后、待办之前插「今天未 shared 的」 | **六源全序**；`kv.proactive_info_id` 载 id、发出后打勾 |
| `interests` 第三源 | `detect_topics` + `recent_convo_topics` + `record_topics` | 累加**放调用方**（`life._browse_one`），不塞进 `sources.py` |
| `stream` 埋点 | `stream.append("browse", "刷了会儿手机，看到：…", now)` | **每轮一条 + 带 1–2 条具体内容**；`now` 必传（实测 #26 旧 bug） |
| 清账 | `_purge_info(now)`：按 `INFO_ITEMS_KEEP_DAYS` 清 `info_items`、按 `HTTP_CACHE_TTL_MIN` 清 `info_cache` | 清账放线程最后，失败不影响刷取 |

## 三、踩坑与实现要点（换来的教训）

### 3.1 `sources.py` 架构约定不能被破——兴趣累加放调用方

方案 §5.4 原文写「`daily_pass` 里对每条 Item 跑 `detect`」，但 `sources.py` 开篇即声明「**不知道自己被谁调用**」、明示「**不 import 业务模块**」。把 `interests` 塞进去会破坏这条约定 → **定稿：累加放 `life` 的刷信息钩子（调用方）**，刷完读新增条目（取刷前 `max(id)` 做差）再喂 `interests`。`sources.py` 保持干净。

做差窗口内混进手动 `/browse` / 网页端「刷一次」落的条目**无妨**（手动刷的同样是"TA 刷到的"），不为此加过滤。

### 3.2 `random_promoted()` 不认 `INTEREST_PROMOTE_ENABLED` 开关

写测试时想在「兴趣 → 旧记忆」这步用 `_patch_config(INTEREST_PROMOTE_ENABLED=False)` 关掉兴趣源，结果兴趣弹照旧命中——因为 `random_promoted()` 走 `promoted()` → `_load()` 读 kv，**并不检查开关**（只有 `detect`/`record`/`prompt_hint` 检查）。测法改成 `_db.set_kv("interests", "")` 清库。**非缺陷，但记一笔**：关开关只停「新增长」，已转正的照旧当弹药。

### 3.3 一视同仁红线的测试要"框住块"而不是"扫全文"

`【我今天刷到的】`块需要证明不含"帮你/为你"这类围绕用户的措辞（§12 一视同仁）。但**全文扫会误报**——`persona` 的通用规则里本来就可能有这些词。改法：`next((m["content"] for m in msgs if "我今天刷到的" in m["content"]), "")` 先定位到**注入块那一条**再断言。

### 3.4 `core` 打勾两个既有瑕疵（本批顺手修）

照抄 `core.py` 的 `proactive_todo_id` 模式时，发现它自身有两处坑，**没有跟着抄**：

1. 打勾代码**包在 `config.TODOS_ENABLED` 门内**——`proactive_info_id` 的打勾与待办开关无关，塞进去会导致关掉待办时 info 永不勾选（同一来源被反复当弹药）。
2. LLM 失败 / 无弹药的 `return False` 路径**不清携带的 id**——陈年 id 会被下一次**任何**主动消息（含非 random 场景）错杀；对 info item 的后果是**误勾 `shared`、永不能再当弹药**。

修法：抽出模块级 `_clear_carried_ids()`（不发/发不出去时清）与 `_settle_carried_ids()`（发出后按 id 打勾，**不包在 `TODOS_ENABLED` 门内**）。

## 四、已知边界（写下来防"忘了"）

- `WORK_ENABLED` 关掉 / **无排班日**（书架空、`day_state.planned` 缺失 → 相位居 `sleep`）：**一天不会自动刷**（手动 `/browse` 照常）。要不要给无排班日留低频兜底，留待后续可议。
- `BROWSE_ENABLED` 关掉：不自动刷、不注入、不弹药（面板开关即"回归今天行为"）。
- **auto ↔ 手动并发**：`_browsing` 只互斥 auto↔auto；`/browse`、网页端「刷一次」直调 `sources.daily_pass`、不吃这把锁 → `info_cache` 去重在 LLM 摘要期间是空白窗，同 URL 理论上可进两条 `info_items`。**小缺口记录在案，本批不为此改 `sources.py`**（实测真出现重复再议；修法是互斥下沉成 `sources` 模块级锁）。
- **第三源是正反馈环**：源单 → items → 兴趣 +1 → 转正进「最近喜欢上的」+ 当弹药 → 对话更容易聊到 → 聊天源再 +1；唯一阻尼是 `INTEREST_PROMOTE_THRESHOLD`。**实测要专门盯转正速度**，异常快可考虑给第三源降权重（数值都在面板可调范畴）。
