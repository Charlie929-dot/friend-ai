# 实测反馈记录 #31（2026-10-10，Web 两 bug：发送排队到回复完才发出去 / 偶发重复消息）

**现象**：①网页端连发多条消息，全部卡在队列里，TA 回复完才一起发出去；②偶发同一条用户消息出现两次。

**根因①（发送排队）**：`webui.py` 的 `/api/send` 处理时套了 `db.PATH_LOCK`，而回复线程 `_reply_worker` 生成回复的**全程**握着 PATH_LOCK（含 LLM 调用 + 打字模拟 sleep，可达几十秒）→ 用户消息的接收被回复生成整个阻塞。换朋友命令（`/friend`、`/new-friend`）内部已自带 PATH_LOCK，外层这把锁对普通消息纯属多余。**修复**：新增 `db.SEND_LOCK`（轻锁）——消息接收/普通命令只与切库互斥（保证消息进哪个库有确定先后序），不与回复生成互斥；`webui` 改用 SEND_LOCK，两个切库命令在 PATH_LOCK 内再套 SEND_LOCK。锁序：切库 PATH_LOCK→SEND_LOCK，收消息只拿 SEND_LOCK，无环。

**根因②（重复消息）**：前端「本地回显 + 900ms 轮询」竞态——消息落库后、POST 返回前，轮询先把这条拉回来渲染，POST 返回又渲染一遍（#25 的 id 游标只防"轮询再渲染"，防不住这个时序）。另外 ① 导致发送挂起几十秒，用户手点重发也会真的发两条。**修复**：前端 `shownIds` Set 按消息 id 去重，回显与轮询谁先到谁渲染、后到的跳过；切朋友时随 resetChat 清空。
