# #51 游戏状态永不过期 → 主动消息被永久封死

**日期**：2026-10-16 · **版本**：发现于 v0.100（读线上聊天记录时），修复待 `docs/方案-对话延续-v0.100.md` 批 1

## 症状

读服务器当天（10-16）与朋友的聊天记录，发现两个说不通的地方：

1. **海龟汤玩到一半，TA 回一句就停**，用户不追问它就永远不问下一个问题（"没有我的触发就不可能继续问问题"）。
2. 用户 22:44 让 TA 找回《Oliver Twist》原文贴过来，TA 答应了（"行，那我去翻"），**之后再无下文**——而它当时正是最有空的时候。

排查时顺手查了 kv，撞见一个**比这两点更急的 P0**。

## P0：`game_state` 不过期，guard 把主动消息永久拦死

```
kv.game_state = {"game": "soup", "started_at": "2026-10-16T22:36:57"}   # 查库时（次日）仍挂着
```

- `game.current()`（`game.py`）只读 kv，**没有任何超时/过期**；退出只认 `corpus.GAME_STOP_WORDS`（"不玩了/结束游戏"…），用户当天一句没说。
- `guard.can_send_proactive` 第 2 条：`if game.current(): return False, "游戏中"`——**游戏进行中拦截一切主动消息**，且这条在 `guard_enabled()` 短路**之前**（guard 默认关也拦）。
- 后果：**从那一次开局起，早安/午间/晚安/随机闲聊/冒泡/轻催/承诺提醒全部停摆**，直到有人说出停止词。这不是"少发几条"，是"这个朋友再也不会自己开口"。

**为什么当时没发现**：游戏开局是静默的（没有可见状态），而"今天它没主动说话"很容易被当成"它刚好没话说"。

## 三个断点（都不是"说话"的问题，是"没人记账"）

诊断与设计全部落在 `docs/方案-对话延续-v0.100.md`，这里只记现象：

1. **游戏没有"该我说话"的状态**：`game.py` 的海龟汤规则只写了"**你当出题人**"，没写"你当猜方时每轮只问一个是/否问题、问完等对方"；再叠加 P0 的"游戏中全拦"，它连自主开口的通道都没有。附带：开局触发词要求**用户**亲口说游戏名（`detect_start`），而"海龟汤"这个名字是 TA 先提的——所以 22:08–22:35 这 28 分钟是**裸跑、规则根本没注入**，开局那次还是用户 22:36 抱怨句里的"海龟汤的规则你也不懂"撞上的。
2. **无时间点的承诺只进记忆、不进队列**：那句"我去翻原文贴给你"**确实被记下来了**（当天 `memories` 两条「计划」："我说这就去翻原文，翻到就一段一段贴给小徐（小徐还没看到这条）"），但记忆不是队列——`events.add_care` 要求**必须有具体时刻**（未来绝对时间）；`todos` 只从"读书素材"和"内心独白【我自己的话题】"进队；`selfmem.self_promise` 要等睡前复盘、且只当六源里优先级最低的弹药。**带时间点的承诺有闹钟，不带时间点的承诺掉进黑洞。**
3. **TA 的话语权来自定时器与骰子，从不来自"我欠你一句话"**：唯一的"接住半截对话"机制是 `nudge`（会话开着 + 空闲 10–20 分 + 60% 概率），内容只是通用催"人咧？"，而且它同样被 P0 的"游戏中"吃掉。

## 处置

- **P0 现场**：直接清服务器 kv（`update kv set value='' where key='game_state'`）——该值每次调用现读，**无需重启即生效**。
- **代码修复**：`方案-对话延续-v0.100.md` 批 1（`game_state` 记 `last_active` + `GAME_IDLE_MINUTES` 过期）。**本批只清数据、未动代码**（用户当次明确"只出方案文档、先别动代码"）。
- **另外两个断点**：同方案批 2（承诺入队）/ 批 3（海龟汤猜方规则）。

## 教训

**任何"会拦住开口通道"的状态都必须有出口。** 与 `quiet_until`（有 hours）、`urgent_until`（有 minutes）、`rest_schedule`（按日重排）不同，`game_state` 是唯一一个**由 LLM 语义触发、却没有到期时间**的状态——语义触发 + 无过期 + 全局拦截，三者凑一起就成了永久静音。加拦截条件时，除了"恒过期的测试"（约定 #10），还得问一句：**这个状态自己怎么退出来？**
