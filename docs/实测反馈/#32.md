# 实测反馈记录 #32（2026-10-10，今日上下文 + 艾宾浩斯记忆衰减，v0.51）

**背景**：用户提议「一天所有信息交流都进记忆，阅读内容存 B 库并注入上下文，写日记后从上下文清除但记忆保留；再加艾宾浩斯遗忘——遗忘=一次次总结，总结够次数彻底遗忘，重复调用延长保持时间，够多次永久记住」。

**落地**：①工作产出素材时顺手落 B 库（`tags=今日素材`，**不额外调 LLM**——素材文本已经生成好了），`context` 每轮注入「你今天做过的事」，筛选条件是"创建于今天" → **跨天自动不再注入**（就是用户要的"写日记后从上下文清除"），B 库记录保留。②`memories` 加 `decay_level`/`pinned` 两列（旧库自动迁移）：距最后一次被想起超过「`IDLE_DAYS ×(1+召回次数×BONUS)`」天 → 压短一级，压到 `MAX_LEVEL` 删行（连带删挂的 B 库长文 + 向量）；`recall_count ≥ PIN_RECALLS` → 永久。

**几个设计取舍**：

- **遗忘挂在睡前复盘里，不另起进程**：一天一次、一次批量 LLM 调用压缩全部待衰减项；LLM 不可用就跳过下次再试（绝不拿空结果误删）。
- **保真优先于衰减**：压缩结果比原文长 / 踩 `_validate` 红线 / 短于 6 字 → 本次跳过不改。总结链漂移是真风险（压三次可能"养猫叫团子"变成"喜欢小动物"），所以宁可不淡忘也不让记忆变味。
- **B 库长文不单独分级衰减**：它是原文证据（书摘/长对话），只在挂着的 A 库记忆被删除时一起删。
- **不做「全量对话常驻上下文」**：`messages` 表本来就是全量记录，真需要靠 `recall` 拿；常驻会让每条消息 token 翻几倍还稀释记忆/人设的权重。
- **命令命名**：`/forget <编号>` 早已被"删事实便签"占用，遗忘命令改叫 `/decay`（`/decay dry` 只预览）。
