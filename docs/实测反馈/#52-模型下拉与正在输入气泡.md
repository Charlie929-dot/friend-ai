# #52 模型下拉看不见 + 聊天区没有「正在输入」（web 两修）

**日期**：2026-10-16 · **版本**：v0.99 遗留，v0.101 修复

## 症状（用户报）

1. 「模型面板下拉并没有显示模型，只是手填」。
2. 「正在输入中的提示」不对——看不到。

## 诊断与修法

### 1. 模型下拉：后端没问题，坏在前端控件

先排除后端（服务器实测）：`config.DEEPSEEK_API_KEY` 已设、`config.DEEPSEEK_BASE_URL = https://api.deepseek.com`，
`llm.list_models()` 正常返回 2 条（`deepseek-flash` / `deepseek-v4-pro`）。`GET /api/llm/config` 也照常带上 `models`。

问题在 `web/index.html` 的模型那一格：

```html
<input id="lmModel" list="lmModels">
<datalist id="lmModels"></datalist>
```

`<datalist>` **不是真下拉**——没有可见箭头，只在部分浏览器（Chrome 桌面）点击/输入时才弹一小条，
**手机 Safari 和相当多内置浏览器根本不支持**，表现就是"什么都没有，只能手填"，与用户描述完全一致。
（v0.99 那条「测试连接自动发现模型」的说明文字承诺了"下拉"，但控件本身撑不起这个承诺。）

**修法**：换成真 `<select id="lmModelSel">`——第一项是「（从下面手填）」，其余是拉到的模型；
选中具体模型就写进下面的输入框，保存仍只读输入框，手填路径不变。`datalist` 删除。

### 2. 正在输入：样式写了从没接线 + 一个 +8 秒假窗口

两个独立问题叠在一起：

- **聊天区根本没有提示**：唯一可见处是右侧「此刻的 TA」抽屉里的一行小字（`index.html` 的 `#typing` + `renderState` 的
  `s.name+' 正在回复…'`，由 `/api/state` 每 900ms 轮询刷新）。而 CSS 里 `.typing-bubble`（三个跳动小点 + `bounce` 动画）
  **全仓库没有任何代码引用**——"聊天区里的正在输入气泡"当初只写了样式。
- **会残留**：`WebChannel.typing_now()` = `generating or time.time() < typing_until`，而 `typing()` 写死
  `typing_until = time.time() + 8`。这是 v0.75 之前「只在发送正文前短暂亮」时代的补丁；v0.75 起 `set_generating`
  已经覆盖「进入回复流程 → 全部段落发完」全程（`core._reply_worker` / `_reply_inbox_worker` 的 try/finally），
  那个 +8 秒只剩副作用：**回复已经到了，气泡还挂着几秒**。

**修法**：①前端把 `.typing-bubble` 接进聊天流（`setTypingBubble`，永远吊在消息流最末、切朋友/收消息都不会乱，
不占左侧目录、不进消息表、不可引用）；②`WebChannel` 不再覆写 `typing()`、`typing_now()` 只读 `generating`，删掉 `typing_until`
与 `import time`。**注意**：主动消息 / 承诺提醒不调 `set_generating`，所以那些时机不显示气泡——**这是有意的**：
"正在输入"的语义是"在回你"，主动消息是它自己开口，直接出现反而真实。

## 测试

在既有 `test_engine` 的「网页端 Web UI」用例里加断言（该用例本来就断言页面结构与 `/api/state` 字段）：
①页面有 `id="lmModelSel"`、且 `lmModels`（旧 datalist）已不出现；②页面有 `setTypingBubble` 与 `typing-bubble`；
③`/api/state` 的 `typing` 在空闲时 False、`ch.generating=True` 时 True、**关掉后立刻 False**（钉住"没有 +8 秒残影"）。
无新增用例函数，`EXPECTED_TOTAL` 不变（89）。
