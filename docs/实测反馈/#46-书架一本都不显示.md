# 实测反馈 #46 · 网页书架一本都不显示（退役函数留了调用点）

> 日期：2026-10-14 · 关联版本 v0.91。详情见 [版本更新记录](../版本更新记录.md)（v0.91 条目）。

## 现象

网页端书架面板**一本书都没有**（显示"书架还空着"），但 `books/` 目录里 23 本 epub 都在、`library.books()` 单跑也能正常返回 23 本。

## 根因

v0.90「生活引擎重构」把**段级进度 `library.progress()` 随跳读一起退役删除**（`library.py` 的 v0.89 注释已写明「段级进度随跳读退役」），但**两个调用点没跟着清**：

| 位置 | 原代码 | 后果 |
| ---- | ---- | ---- |
| `webui.py` `/api/books` | `"progress": _lib.progress()` | 抛 `AttributeError` → 整个接口 500 → 前端只拿到 `{"error": ...}` |
| `commands.py` `/books` | `prog = _lib.progress()` | 命令同样炸（"← 正在读"标记那段） |

前端 `loadBooks()` 拿到的 `bkData` 没有 `books` 字段 → `(bkData.books||[]).length === 0` → 渲染成空书架。**注意 `fetch` 对 500 不抛异常**，所以静默地空掉、控制台也不显眼。

## 为什么本机看着是好的

本机 web 服务是**改动之前启动的旧进程**（`web.pid` 时间早于 `library.py` 改动），进程内存里还是改动前的 `library` 模块（还有 `progress`）→ 本机接口照常返回 23 本。**本机服务一重启就会和服务器一样变空**——所以这个 bug 只在「重启过的部署」上暴露。

## 修法

- `life.py` 新增 `reading_book(now=None)` —— 今日在读的那本书 id（`today().plan.book_id`），作为「**在读哪本**」的唯一来源。
- `webui.py` `/api/books` 的 `progress` 字段改 `{"book_id": life.reading_book()}`；`commands.py` `/books` 改用 `_life.reading_book()` 取 `cur_id`。
- **前端字段名不变**（仍是 `progress.book_id`），`web/index.html` 一行未动，「正在读」徽章自动恢复。
- 顺带清理 `books/categories.json` 里一条历史残留死条目（`测试书.txt`，书架里并无此文件）。

## 教训

1. **退役一个函数，必须全项目 grep 调用点**——`library.progress` 被删时只改了"自己人"，漏了 `webui` / `commands` 两个消费方。删公开函数前先 `grep -rn "\.function_name("`。
2. **接口异常被 `except` 吞成 500 时，前端会静默空掉**——前端对 `{error}` 响应没有可见降级提示，只当"没有数据"渲染空态。这类"空态"最像"功能没做"，排查时先 `curl` 一次原始接口再怀疑数据。
