## 二、Docker Hub 在服务器上不通（新踩坑）

`sudo docker pull hello-world` → `dial tcp [2a03:2880:...]:443: i/o timeout`（Docker Hub 被墙，IPv6 路由超时）。

**修法**：写 `/etc/docker/daemon.json` 加镜像源，按可用性排序：

```json
{ "registry-mirrors": ["https://mirror.ccs.tencentyun.com",
                       "https://docker.m.daocloud.io",
                       "https://docker.1panel.live"] }
```

- 实测 `mirror.ccs.tencentyun.com/v2/` → 200（**腾讯云轻量内网源，用它最快**，拉 `diygod/rsshub` 16 秒）；`docker.m.daocloud.io` → 401（可达）；`dockerpull.org` → 不通。
- ⚠️ **重启 docker 会波及 derper**（Tailscale 中继容器）。本机 derper 是 `restart=unless-stopped`，实测重启后自动拉起、无中断。改 daemon.json 前先 `docker inspect derp --format '{{.HostConfig.RestartPolicy.Name}}'` 确认。
- ⚠️ `ubuntu` 用户**不在 docker 组**，所有 docker 命令要 `sudo`。

## 三、RSSHub 自建（把"没干净 RSS 的源"变成 RSS）

- 部署形态：`/opt/rsshub/docker-compose.yml` + `.env`（`docker compose up -d`），容器只绑 `127.0.0.1:1200`（**不对外暴露**）、`restart: unless-stopped`。
- `GITHUB_ACCESS_TOKEN` 走 `.env`（GitHub Trending 路由没有 token 直接 `503 ConfigNotFoundError`）。

## 四、五种源的可行性实测结果（这是本批最值钱的结论）

| 源 | 实测 | 结论 |
| --- | --- | --- |
| 人民日报 | `people.com.cn/rss/politics.xml` → RSS 2.0，**100 条** | ✅ 原生 RSS |
| Nature | `nature.com/nature.rss` → **RSS 1.0 / RDF 格式**，75 条 | ✅ 但**必须同时认 RSS 1.0** |
| 果壳科学人 | RSSHub `/guokr/scientific` → 10 条 | ✅ |
| bilibili | RSSHub `/bilibili/ranking/all`（29 条）/ `/bilibili/precious`（98 条）可用；`/bilibili/hot-search`、`/bilibili/ranking/:rid/:type` **需容器内 Playwright 浏览器**（`browserType.launch: Executable doesn't exist ... chrome-headless-shell`） | ✅ 走 `ranking/all` 这类不需要浏览器的路由 |
| GitHub Trending | RSSHub `/github/trending/daily/any` | ✅ 但**必须配 `GITHUB_ACCESS_TOKEN`** |
| 微博 | `/weibo/search/hot` → 需 **Playwright + 微博访客 Cookie**（还报 `Cooling down before new visitor Cookies`）；手机端 `m.weibo.cn` 接口 → 302；网页端反爬 | ❌ **现有通道下不可行，已砍** |

**两个必须记住的实现约束**（都已在 `sources.py` 落地）：

1. **RSS 1.0 (RDF) 也要认**——Nature 用的就是它（`<item rdf:about=...>`、默认命名空间是 `purl.org/rss/1.0/`）。只按 RSS 2.0 的 `channel/item` 取，Nature 会一条都出不来。修法：**一律按标签本地名（`tag.rsplit('}',1)[-1]`）匹配** `item`/`entry`，RSS 2.0 / RSS 1.0 / Atom 三种命名空间一视同仁。
2. **冷缓存首击会瞬时 503**——bilibili 路由改完容器后第一次访问返回 503，紧接着连打三次都是 200（上游风控/缓存重建）。所以取数失败**必须降级成"今天没刷到"**，不能当异常抛（本批已按此实现并在 `test_source_fetch_cache` 里守住）。

## 五、订阅表存放位置的坑（`sync-to-server.sh` 会冲掉被追踪的文件）

`sync-to-server.sh` 第 51 行是 `git checkout -- . ; git pull --ff-only`——**任何进 git 的运行时数据在服务器上每次同步都会被冲掉**。所以 `sources.txt` **必须 gitignore**（与 `books/*` 同理），出厂种子放 `sources.py` 的 `DEFAULT_SOURCES`（代码里），这样新部署开箱即用、用户改的源又不会被同步覆盖。
