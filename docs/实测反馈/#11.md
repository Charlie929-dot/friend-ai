# 实测反馈记录 #11（2026-10-07，记忆主动检索落地）

**功能落地：function calling 让 AI 主动查记忆（MCP tool 阶段）**

- 需求：用户描述——"反复要求回忆时 TA 会自己调用 MCP 慢慢检索 A 库，而不是只根据上下文回应"。对应需求池「AI 自主行为接口（MCP）」的记忆检索部分
- 落地（2026-10-07）：
  1. **llm.chat_with_tools**：带 tools 参数的 function calling 调用，返回 {content, tool_calls}，无 key 降级 stub
  2. **memory.MEMORY_TOOLS**：两个工具——search_memories（查 A 库摘要，长内容给摘要+标记）、recall_detail（展开 B 库全文）；run_memory_tool 执行并渲染结果（自包含，避免 memory↔context 循环依赖）
  3. **memory.wants_memory_search**：回忆/追问信号识别（"记得/回忆/当时/详细/说说"等），普通闲聊不触发
  4. **core 工具循环**：\_generate_reply_text 按信号分流——普通聊天走 llm.chat 快速路径（省 token 省延迟）；回忆信号下走 \_chat_with_memory_tools（最多 MEMORY_TOOL_MAX_ROUNDS=3 轮，执行工具回填 tool 消息，超限无文本时无工具兜底）
- 设计取舍：**不每轮都带 tools**——只回忆/追问时启用，否则日常聊天成本、延迟增加，AI 也可能过度调用。程序自动召回仍是第一层兜底，function calling 是"主动深挖"
- 测试：新增 test_memory_tool_calling（信号分流/tool loop 回填/普通聊天快速路径/开关降级），全量 36 项通过
